<objective>
## Goal
Give the coach an arbitrary window instead of five fixed bins. A new card beside Time-to-Distance
offers one chip per complete 5 m (or 5 yd) segment of the swim; clicking them selects a
**contiguous** run — 0–10, 5–15, 0–15 — and reads back that window's **average velocity and
elapsed time**, shading the exact span on the velocity trace above.

## Purpose
Reported defect 1, verbatim: *"there's only splits for every 5m... The user should be able to
select every 5 meters, like a toggle effect, and see what the avg velocity and time are. So they
can do 0-10, or 5-15 or 0-15."* The registry splits are fixed bins with usual-range history; this
is an ad-hoc window for this one swim. Both jobs are real, which is why CONTEXT D1 keeps the grid
rows and adds a card rather than replacing them.

## Output
- new pure `web/lib/splitWindow.js` — bin construction and window measurement, no React
- new `web/components/portal/SplitPicker.js` — the card
- an optional `spanS` prop on `VelocityChart` and `AccelerationChart`, drawn as a shaded
  `ReferenceArea`
- `page.js` mounts the card in `middleSlot` and owns the span state
- `scratch/split_picker_check.mjs` — pure-lib assertions plus a render check
</objective>

<decisions>
Made by me at the user's direction, 2026-08-31.

**D1 — Open question 6 answered by NOT competing: the picker does not touch `onMarkerChange`.**
It gets its own `spanS` prop on the two charts, drawn as a shaded `ReferenceArea`, and TimeToX
keeps the amber `ReferenceLine` untouched. Two cards writing one marker is a live conflict —
TimeToX's marker effect re-fires on every dependency change and would stomp the picker — and it is
also the wrong drawing: a *window* is not a *point*. A span is both correct and conflict-free, and
it costs about eight lines per chart.

**D2 — Open question 5 answered by refusing partial segments: only COMPLETE bins are offered.**
This deletes R5 outright. `TimeToX` already sets the precedent by hiding presets the swim never
reached (`TimeToX.js:44`), so a coach already expects the chips to describe what happened. On a
25-yard lap the last ~1.9 m is therefore absent from the picker — and that stretch is exactly what
88-01's `splits_remainder` row now reports in the grid below. Each surface stays honest about what
it is showing, and there is no partial label like "20–25" to lie about a 1.9 m window.

**D3 — No default selection, and therefore no span on the chart until the coach picks one.**
The velocity chart is the page's hero and is shared with the acceleration trace and the video
panel. A card that shades it on every page load would change the chart for every coach whether or
not they use the picker. Empty state reads "Tap segments to measure a window."

**D4 — The window's average velocity is the CHORD:
`(dist[i1] - dist[i0]) / (t[i1] - t[i0])`.** Not a sample mean of `vel`. This is 88-01's D4, and it
is what makes AC-2 possible: a single-bin selection reproduces the matching grid split *exactly*,
not approximately, because `_split_velocity` computes the same two indices from the same anchor.
⚠ It also means the search window is clamped at `finish_s` exactly as `_split_velocity` clamps it
— without that clamp a bin could be filled by the swimmer drifting into the wall after the touch
(PROJECT.md constraint, 2026-08-28), and the two numbers would silently diverge.

**D5 — Interaction: click extends the contiguous run; clicking inside it collapses.**
CONTEXT D8 asked for "toggle contiguous segments" and gave the example. Concretely, with the
selection held as an inclusive `{lo, hi}` bin-index pair (contiguity is then structural, not
enforced):
  - nothing selected, click k → `{k, k}`
  - k outside the run → `{min(lo,k), max(hi,k)}` — clicking 0–5 then 10–15 fills 5–10, as asked
  - k inside a multi-bin run → collapse to `{k, k}`
  - k is the only selected bin → clear
A from/to boundary picker was the alternative and was rejected: it needs two controls and cannot
express "toggle".

**D6 — Bins are unit-native (CONTEXT D5): 5 m in metric, 5 yd (4.572 m) in imperial.** Matching
`TimeToX`'s existing chip semantics. ⚠ The grid's split rows stay metre-binned, so in imperial the
picker's "0–5 yd" and the grid's "Split 0–5 m" are different windows. Accepted by CONTEXT — but the
card says so in one line, shown only in imperial. A coach who cannot see the disagreement cannot
reason about it.

**D7 — Open question 1 answered better than "do not render": the picker uses the SAME `anchorS`
the rest of the page uses**, the const 88-02 hoists — including its `baseline_end_s` fallback. A
special case here would reintroduce a second anchor in the one place nobody looks. The card renders
whenever `anchorS != null` and at least one complete bin exists; otherwise it renders an empty
state, not a broken chip row.

**D8 — `finish_s` falls back to the end of the trace**, mirroring `_finish_s`
(`phase_metrics.py:660-671`) rather than inventing a second rule. A session whose finish never
resolved still has a measurable swim.

**D9 — The card is placed immediately after Time-to-Distance inside `middleSlot`** — CONTEXT D1's
"beside Time-to-Distance". Same section chrome as its neighbours so it reads as one of the page's
cards, not a new kind of thing.
</decisions>

  <name>Task 1: The pure window library</name>
  <files>web/lib/splitWindow.js</files>
  <action>
    New pure module in the style of `web/lib/windowMetrics.js` — no React, no Next, node-loadable,
    formulas documented against their `phase_metrics.py` counterpart.

    ```
    export const YARD_TO_M = 0.9144;   // same constant TimeToX uses
    export const BIN_U = 5;            // 5 m, or 5 yd in imperial (D6)

    export function buildBins({ dist, time, anchorS, finishS, fsHz, imperial })
      -> [{ k, fromU, toU, i0, i1 }]   // COMPLETE bins only (D2)

    export function measureWindow(bins, sel)   // sel = { lo, hi } | null
      -> { fromU, toU, i0, i1, avgVelMs, elapsedS } | null

    export function toggleBin(sel, k)          // D5, pure
      -> { lo, hi } | null
    ```

    - `buildBins`: `i_anchor = Math.round(anchorS * fsHz)`; `d0 = dist[i_anchor]`; clamp the search
      at `Math.min(dist.length, round(finishS * fsHz) + 1)` (D4/D8). `step = imperial ? BIN_U *
      YARD_TO_M : BIN_U`. Walk once, recording the first index at which `dist[i] - d0 >= k * step`
      for k = 0, 1, 2…; a bin k is emitted only when the boundary for k+1 was found. Skip
      non-finite distance samples (stored profiles carry dropout nulls — `_finite_slice` is the
      backend's equivalent guard). Return `[]` on a missing anchor, an out-of-range anchor index,
      a non-finite `d0`, or fewer than two boundaries.
    - `measureWindow`: `i0 = bins[sel.lo].i0`, `i1 = bins[sel.hi].i1`;
      `elapsedS = time[i1] - time[i0]`; `avgVelMs = (dist[i1] - dist[i0]) / elapsedS`, null when
      `elapsedS <= 0` or either distance is non-finite. **Chord, never a sample mean (D4).**
    - `toggleBin`: exactly D5's four cases.
    - Header comment states D4 with the `_split_velocity` cross-reference and D2's
      complete-bins-only rule.

    Avoid: a partial trailing bin (D2); averaging `vel` (D4); searching past `finishS` (D4);
    enforcing contiguity with extra code — the `{lo, hi}` shape makes it structural.
  </action>
  <verify>node scratch/split_picker_check.mjs — the pure-lib block (Task 4)</verify>
  <done>AC-1's model, AC-2's arithmetic and AC-3's rule all exist in one pure file.</done>
