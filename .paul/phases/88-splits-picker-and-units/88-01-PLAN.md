<objective>
## Goal
Retire the split that can never fill and replace it with the part of the race that actually
exists. `splits_25m` leaves the registry; a new `splits_remainder` measures mean velocity from
the 20 m mark to `finish_s`. The report card stops rendering the dead row on sessions that have
not yet been recomputed, and the library is backfilled through the existing recompute path.

## Purpose
CONTEXT F2 / STATE item 16: the tether is on the waist, so a 25-yard lap (22.86 m) records only
~21.9 m of travel. `splits_25m` fills on **2 of 99** stored sessions — structurally, not by
failure. A coach reads that row as a broken number, which is exactly what was reported. The
closing metres of the swim are real and currently have no row at all.

## Output
- `_dive_relative()` extracted from `_split_velocity` (shared anchor block, no behaviour change)
- `_remainder_velocity()` + `_MIN_REMAINDER_M` in `phase_metrics.py`
- registry: `splits_25m` out, `splits_remainder` in
- `DIRECTION_OF_GOOD` + `DISPLAY` entries, plus a `RETIRED_KEYS` skip so a not-yet-recomputed
  session does not render the dead row off its stored label
- two fill counters in `tools/backfill_phases.py`, read at the backfill checkpoint
</objective>

<decisions>
Made by me at the user's direction (*"any decision is up to you to do what's consistent with
history and what makes the most sense"*), 2026-08-31. Several were settled by reading the live
code rather than by preference — those say so.

**D1 — Key is `splits_remainder`, label "Split 20 m to finish", unit `m/s`, tier `low`,
direction-of-good `up`.** CONTEXT D3 already fixed that this is a NEW key rather than a relabel of
`splits_25m`, so the usual-range band only ever sees one definition. The four surviving bins keep
their keys and their history untouched.

**D2 — No `SCHEMA_VERSION` bump.** Verified, not assumed: the version tracks the *shape* of the
`phases` object — `2` added `boundaries`, `3` added the per-metric `provisional` flag, `4` added
`kick_bands` (`phase_metrics.py:32-35`). 75-06 added twenty-three metrics without touching it.
Registry membership is not schema shape, and `tests/test_phase_metrics.py:1035` pins `== 4`, so
bumping would break a test that is asserting the right thing.

**D3 — The minimum span is a distance floor, `_MIN_REMAINDER_M = 1.0`, and it is MEASURED at the
backfill checkpoint before it is trusted.** R4's worry is real but its stated reason is not the
binding one: ~1.9 m at ~1.8 m/s is ~1.06 s, about 95 samples at 89.5 Hz — not sample-starved. What
actually breaks is a swim that crosses 20 m and stops: a 0.2 m tail is arithmetically fine and
physically meaningless. 1.0 m is the tether's own head-waist scale (PROJECT.md: arm plus torso
about 1 m) and leaves the common 25-yard case (~1.9 m) reporting. ⚠ 83-03 is the precedent for not
shipping an unmeasured cutoff — Task 3 adds the counters and Task 5 reads them before `--apply`.

**D4 — The remainder is the SAME chord arithmetic as the fixed bins: delta-distance over
delta-time.** Not a sample mean of `vel`. `_split_velocity` has always used the chord, and a coach
reading the new row directly beneath four chord rows must be reading the same kind of number. It
also makes 88-04's picker able to reproduce a grid bin exactly, which is that plan's AC-2.

**D5 — The anchor block is EXTRACTED, not duplicated.** `_split_velocity`'s first eleven lines
(dive index, `d0`, finish clamp, `rel`) are exactly what the remainder needs. Two copies of a
"where is 0 m" rule is how the page grew three of them in the first place (CONTEXT F5). ⚠ This is
a refactor of working code, so AC-2 requires the four surviving split values to be unchanged —
`test_split_tracks_the_segment_it_covers` already pins two of them to hand arithmetic.

**D6 — `RETIRED_KEYS` on the client, because the row model renders whatever keys the stored object
carries.** `PhaseReportCard.js:437` iterates `Object.entries(phaseObj)` and falls back to
`{ label: m.label, unit: m.unit }` when `DISPLAY` has no entry. So simply deleting the `DISPLAY`
entry would keep the dead row rendering off its stored spec label until the backfill reached that
session — a worse failure than today's, because the `emptyNote` explaining the blank would be gone
too. An explicit skip set is the honest instrument and it survives the next retirement.

**D7 — The backfill is the EXISTING `tools/backfill_phases.py`, user-run at a blocking
checkpoint.** Verified, not assumed: that tool already performs precisely this derivation
(`compute_phases` over the stored profiles, `metrics_json.phases` replaced, everything else
untouched, idempotent) and it is what 75-02 / 75-06 / 83-02 all used. **No new tool.** User-run
follows the 87-01 precedent, and its `--dry-run` mode is what makes D3 measurable before a write.
</decisions>
