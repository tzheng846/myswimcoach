<objective>

## Goal
Add an **overlay panel** beneath the Swimming and Underwater phase insets: every stroke cycle (or
downkick) drawn on one shared axis, all in neutral grey, with a left gutter of numbers that highlights
one trace on hover and pins it on click. Seconds x-axis by default, a normalized (% of cycle) toggle
that adds a pointwise-median reference line.

## Purpose
83-03 measured that no MAD threshold separates a clean swim from a ragged one at a median of 7 cycles
per lap — it fired on 75% of sessions at `k=3.0` and still 39% at `k=8.0`. The honest replacement for a
classifier that cannot work at this sample size is to **show the strokes and let the coach's eye do
it**. This makes every per-cycle number in `CycleCharts` auditable against the shape it came from,
which is the same "make segmentation visible" goal Phase 83 opened with.

## Output
- New pure lib `web/lib/cycleTraces.js` (+ `scratch/overlay_checks.mjs` node checks)
- New component `web/components/portal/phases/CycleOverlay.js`
- `PhaseReportCard.js` wires both panels and lifts the pin state
- `cycleShape.js` header comment corrected (it is no longer fully parked)

</objective>

  <files>web/lib/cycleTraces.js, scratch/overlay_checks.mjs, web/lib/cycleShape.js</files>
  <action>
    New pure module. No React, no SVG geometry — data in, data out, same posture as `cycleBands.js`.

    Export `buildTraces(items, velocity, { fsHz, mode, durationKey = "duration_s", excludeBreakout })`
    returning `{ rows, traces, median, maxDuration }`:

    - `rows` — the GUTTER MODEL, built ONCE from the stored array and IDENTICAL in both modes
      (this is AC-4's renumbering guarantee and R2's fix). One row per item:
      `{ n, available: bool, reason: null | "dropout" | "breakout" | "too-short" }`.
      `n` uses the SAME rule as `cycleBands.buildBands` — `cycle_num + 1` when stored, else array
      position + 1 — because it is the cross-highlight key shared with CycleCharts. Do not invent a
      second numbering.
    - `traces` — only the drawable ones: `{ n, points: [[x, v], ...] }`.
      - `mode: "seconds"` → `x = (i - start_idx) / fsHz`, real velocities, non-finite samples become
        a BREAK in the point list (the component lifts the pen), NOT a dropped trace.
      - `mode: "normalized"` → `x = j / (POINTS - 1)`, values from `cycleShape.resample()`. A null
        return (any non-finite sample, or span < 2) means the trace is omitted and its row is marked
        `available: false, reason: "dropout"`.
    - `median` — normalized mode ONLY, and only when `traces.length >= cycleShape.MIN_ITEMS` (5).
      Pointwise median across the resampled traces. Reuse the median helper rather than writing a
      second one. `null` otherwise. Never computed in seconds mode: a pointwise median needs a common
      x-grid and seconds mode has none.
    - `maxDuration` — the longest trace's duration in seconds, so the component can size the x-axis.

    IMPORT `resample`, `POINTS`, `MIN_ITEMS` from `./cycleShape`. Do NOT import `analyzeShapes` and do
    NOT touch its MAD gate — that gate is the measured failure from 83-03 and stays parked (STATE
    item 17 is still open).

    Then UPDATE the header comment of `web/lib/cycleShape.js`: it currently says "PARKED, NOT WIRED.
    Nothing imports this." That becomes false the moment this task lands. Rewrite that paragraph to
    say `resample` + the median ARE wired (by `cycleTraces`, for the overlay's normalized mode) while
    `analyzeShapes`' MAD gate remains parked and unimported, and keep the measured numbers. Leaving it
    false is the exact defect 83-03 had to come back and fix in `cycleBands.js:9`.

    Write `scratch/overlay_checks.mjs` following the `scratch/shape_checks.mjs` pattern (plain node,
    no test runner, prints N/N). Cover at minimum: gutter rows identical across both modes; `n`
    matching `buildBands` for both a `cycle_num` array and a `kick_num` array; a dropout trace present
    in seconds and absent-but-listed in normalized; median null below 5 traces and present at 5; empty
    and single-item arrays returning no traces.
