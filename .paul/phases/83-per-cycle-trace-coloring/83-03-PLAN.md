<objective>
## Goal
Replace the unexplained gold halo with a flag that **means something**, and say what it means:

1. **Shape-based anomaly detection (primary).** Each cycle/kick is resampled to a fixed length and
   compared against the session's own **median profile**; the flag fires only when a band's deviation
   clears a within-athlete **MAD gate**, so a clean swim shows **no flag at all**.
2. **Duration as a secondary, provenance-qualified fact** — surfaced in hover, never as the red.
3. **Re-assigned colours:** breakout stroke **GOLD**, anomalous band **RED**.
4. **Hover copy that explains which flag fired and why.**

## Purpose
The current flag is not an abnormality test. `buildBands` marks the single furthest-from-median
duration with **no threshold**, so exactly one band is gilded on every session with ≥3 bands however
tight the spread — and nothing in the UI explains it. Worse, duration is the one quantity the
segmenter itself manufactures: with `segmentation_reliable` hardcoded `False` and freestyle boundary
F1 at **0.458** (Phase 59), a duration outlier on an auto-segmented session is more likely a
mis-placed boundary than a bad stroke. **The current feature largely flags the segmenter.**

Shape is duration-normalised by construction, so it degrades gracefully under boundary error where
duration changes discontinuously. It is also what a coach means by "that stroke looked different" —
where the peak sits, how deep the dead spot is — and it is *showable*.

## Output
- New pure `web/lib/cycleShape.js` — resample, median profile, MAD gate. No React, no SVG.
- `buildBands` emits `flag: "breakout" | "anomaly" | null` plus `isBreakout`, replacing `outlier`
- New `--color-cycle-breakout` / `--color-cycle-anomaly` tokens in the **`@theme static`** block
- Gold breakout band (Swimming only) + red anomaly halo, on both the Swimming and Underwater insets
- Hover copy naming the flag, its magnitude in m/s, and the boundary provenance
- **No backend change.** `metrics_json` and `schema_version` (4) are untouched.

<task type="auto">
  <name>Task 1: Pure shape analysis lib</name>
  <files>web/lib/cycleShape.js, scratch/shape_checks.mjs</files>
  <action>
    New pure module. No React, no SVG, no wording — same posture as `cycleBands.js`.

    Export `analyzeShapes(items, velocity, opts)` returning, per input item, `{ n, shapeDist,
    durationDev, anomaly }`, plus the reference profile so the UI could draw it later.

    Algorithm, in this order:
    - **Resample.** For an item spanning `[start_idx, end_idx)`, sample `points = 50` values at
      evenly spaced fractional positions across the span, linearly interpolating between neighbouring
      samples. This is what makes the measure duration-invariant (AC-1).
    - **Exclude, do not guess.** An item whose slice contains any non-finite value, or spans fewer
      than 2 samples, is excluded from the reference AND returned unflagged. Do not interpolate over
      dropouts here — `detect_underwater_kicks` fills them because peak *shape* survives it, but a
      distance measure would silently score the fill.
    - **Reference = pointwise MEDIAN** across the included resampled items, not the mean. One bad
      cycle must not drag the thing it is being compared against.
    - **Distance = RMSE in m/s** against the reference, on raw velocities. Deliberately **not**
      Pearson correlation: Pearson is scale- and offset-invariant, so it would discard amplitude, and
      a weak pull with a normal profile is exactly what should be caught. RMSE also gives the hover
      an interpretable unit.
    - **Gate.** `med = median(dists)`, `mad = median(|dist − med|)`. Flag item i when
      `dist_i − med > k · mad`, with **`k = 3.0`** (MAD·1.4826 ≈ σ, so k=3 is roughly a 2σ-equivalent
      ≈ 1-in-20 rate). **One-sided** — a band closer to typical than typical is not an anomaly.
      Require **`minItems = 5`** and **`mad > 0`**; below either, flag nothing. Name `k`, `points`
      and `minItems` as exported constants with these rationales in comments so they are tunable at
      the human-verify without hunting.
    - **`durationDev`** = the signed deviation of the item's duration from the median duration, in
      MADs, computed on the same robust basis. **Two-sided** (long and short both matter). This is
      returned as a FACT for the hover — it must not, on its own, set `anomaly`.

    Also write `scratch/shape_checks.mjs`: a node harness printing pass/fail counts over synthetic
    fixtures — two identical profiles at different durations scoring equal distance; a
    reduced-amplitude profile scoring higher; a uniform set flagging nothing; one injected odd cycle
    flagging exactly itself; fewer than `minItems` flagging nothing; a zero-MAD set flagging nothing;
    a NaN-bearing item excluded and unflagged.
    ⚠ `web/package.json` has no `"type": "module"`, so node cannot import `web/lib/*.js` directly.
    Have the harness copy the lib to a `.mjs` under `scratch/` and import that.

    Avoid: any dependency (there is no test runner and none is being added), emitting display strings
    from this lib, and normalising amplitude — that last one is a deliberate design choice, not an
    oversight.
  </action>
