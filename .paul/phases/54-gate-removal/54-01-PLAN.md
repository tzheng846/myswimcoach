<objective>
## Goal
Remove every account-level restriction and stroke gate for all accounts, behind reversible
switches. Tier limits go off by default via one env var; breaststroke-only analytics gating is
lifted so freestyle sessions render full ratings on backend and iOS.

## Purpose
Immediate: the free-tier `device_limit` of 1 blocked a test today, and `monthly_session_limit` of 20
would 402 partway through the Phase-53 pool day (10+ baseline trials plus warm-ups and perturbation
pairs). Both would waste a collection session that depends on hardware, pool time, and a swimmer.

Strategic: billing is not being sold yet and the stroke restriction blocks the freestyle work Phase
53 depends on. Both restrictions are premature for where the product actually is.

## Sequencing note (revised 2026-08-03)
`depends_on` was `["51-02"]` on the assumption 51-02 would land first. Verified at apply time:
`grep ENFORCE_ api.py` returns 0 hits, so **51-02 has NOT landed** and this plan applies against the
current file instead. Consequence to act on:

> **51-02's athlete-limit task is now REDUNDANT.** This plan wraps the athlete limit under
> `ENFORCE_TIER_LIMITS`. When 51-02 is applied in the other environment it must NOT also add
> `ENFORCE_ATHLETE_LIMIT` — that would double-gate the same block and leave two switches for one
> concern. Drop that task from 51-02; keep its real fix (the four phantom `athletes.coach_id`
> sites → `team_id`) untouched, which this plan does not address.

Phase 52 DID land before this plan. It shifted the `segmentation_reliable` sites (now api.py:182,
192, 481, 879) but left the three tier-limit blocks at their original lines — those references below
are current.

## Decision: `segmentation_reliable` stays as-is (2026-08-03)
Task 2 removes `ratings.py` as its only functional consumer, leaving the flag as inert provenance
metadata (`metrics.py:617` writes `bool(manual_bounds)` — "did a human draw these boundaries?").
It is deliberately NOT flipped to default-True and NOT renamed:
- flipping it would record something false, and would destroy the one marker distinguishing Phase
  53's 10 hand-annotated sessions from auto-segmented ones;
- renaming it to `segmentation_source: "auto"|"human"` is the clean fix but is deferred — after this
  plan nothing reads it, and the consumer that eventually will is Phase 53's measurement layer,
  which has not defined its vocabulary yet. Deferred item recorded in Phase 53's open questions.

No client reads this flag today (web: zero references; the mobile "Segmentation is experimental"
caption at ReportCardScreen.js:470 is a hardcoded string).

## Output
- `api.py` — single `ENFORCE_TIER_LIMITS` kill switch, default OFF, covering all three limits
- `ratings.py` — bands apply to every stroke; `provisional` no longer keys off segmentation
- `tests/test_ratings.py` — two contradicted tests inverted to assert the new contract
- `ReportCardScreen.js` — `isAnalyticsReady` always true
