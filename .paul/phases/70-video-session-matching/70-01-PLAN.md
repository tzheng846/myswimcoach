<objective>
## Goal
Ship the **manual-matching core** (CONTEXT D1–D3): a new web page where a coach dumps many opaque
external clips, sees a **content thumbnail** of each (so the swim is recognized, not guessed from a
filename), and assigns each clip to a session — reusing Phase 69's `POST /sessions/{id}/videos`.
No schema change, no new endpoint, no server CV, no camera/clock assumptions.

## Purpose
The live annoyance (user, Phase 70 CONTEXT): *"it's super annoying trying to pick what video matches
with what session."* GoPro/off-brand filenames (`GX010042.MP4`) and metadata are untrustworthy (D2),
so the only honest signal is **what the clip filmed**. Phase 71 already fixed single-add (report-card
modal) and the store/reader split; the remaining pain is pairing MANY clips across MANY sessions in one
sitting — a cross-session batch surface that no per-session page can be.

## Output
- New route `web/app/app/match/page.js` — multi-file staging, client-side thumbnails + soft metadata
  hints, per-clip session picker, assign-to-session via `POST /videos`.
- A "Match videos" entry in the portal nav (`layout.js`).
- `.paul/phases/70-video-session-matching/70-01-SUMMARY.md`.
</objective>

    - **Staging (client-side only, no upload here):** an `<input type="file" accept="video/*" multiple>`
      ("Add clips"). On change, append each `File` to a `clips` state array as
      `{ id, file, url: URL.createObjectURL(file), thumb: null, durationS: null, status: "staged", error: null, sessionId: "" }`
      (`id` = a stable per-clip counter — NOT Math.random/Date.now, which are unavailable/undesired; use an
      incrementing ref). Reuse the AddVideoModal 50 MB constant + client size check to pre-flag over-cap clips
      (set a soft warning on the card; still allow staging so the coach sees the thumbnail).
    - **Thumbnail + duration (client-side canvas, CONTEXT design-call #2 = client-side, server-light, no schema):**
      a helper `grabThumb(url)` that creates an offscreen `<video>` (`preload="metadata"`, `muted`, `playsInline`,
      `src=url`), waits for `loadeddata`, seeks to `min(1, duration*0.1)`, waits for `seeked`, draws the frame to a
      `<canvas>` sized to the video's intrinsic aspect (cap width ~320px), and returns `{ dataUrl: canvas.toDataURL("image/jpeg", 0.7), durationS: video.duration }`. Object URLs are same-origin (no canvas taint). Run it per clip
      after staging (in an effect keyed on clips lacking a thumb); write `thumb`/`durationS` back. On failure, leave
      `thumb=null` and show a "no preview" placeholder — never block the card.
    - **Grid:** render staged clips as a responsive grid of cards (reuse Tailwind tokens/classes seen in the portal
      — `border-surface-3`, `bg-surface`, rounded-2xl, etc.). Each card shows: the thumbnail (or placeholder), the
      filename, and **plain soft hints** — duration (mm:ss), size (MB, red if >50), and the file's `lastModified`
      as a local date/time. ⚠ Hints are DISPLAY ONLY — do NOT sort, rank, or pre-select sessions by them (D2). A
      per-card "Remove" button revokes its object URL and drops it from state.
    - **Cleanup:** revoke all object URLs on unmount (effect returning a cleanup that iterates current clips).
    - **Nav:** in `layout.js`, add `{ href: "/app/match", label: "Match videos" }` to the `navLinks` array
      (after Sessions). Nothing else in layout changes.
    - Leave the session picker + Assign for Task 2 — Task 1's cards render with a disabled/placeholder picker slot.
    Avoid: any upload in this task; any new npm dependency; storing thumbnails server-side; Math.random()/Date.now().
