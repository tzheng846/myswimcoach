<objective>
## Goal
Put a **cycles / strokes** toggle in the Swimming section of the coach report card. In stroke mode
the four Swimming surfaces switch together — the inset's per-cycle bands, the count badge, the
`CycleOverlay` pack, and the four `CycleCharts` panels — from `metrics_json.cycles` to
`metrics_json.strokes`, and a new **Arm balance** readout renders the three signed asymmetry
percentages plus the four per-side CVs that 87-01 stored.

## Purpose
87-01 makes the individual arm stroke a stored unit and measures a signal that separates — **6.1%
median tempo contrast** across 23 annotated freestyle sessions, 0.4% on the evenest and 29.4% on
the most lopsided. None of it is reachable: the report card only knows how to draw cycles, and a
cycle contains both arms, so its A/B contrast is structurally zero. This plan is the only thing
that turns a stored array into something a coach can see.

## Output
- `numberKey` seams on `cycleBands.js` and `cycleTraces.js`; per-side tint + per-side medians in
  `cycleTraces.js`
- new pure `web/lib/strokeStats.js` — stroke-level means/CVs and the arm-balance display model
- optional `itemLabel` on `CycleCharts` / `TrendPanel`, `colorByParity` on `CycleOverlay`
- the toggle, the Arm balance block and the wiring in `PhaseReportCard.js`
- `scratch/stroke_toggle_check.mjs` — headless render check in the 83-05 / 85-01 pattern
</objective>

<decisions>
Made by me at the user's direction (*"all decisions are up to your recommendations"*), 2026-08-31.
Several were settled by reading the live code rather than by preference — those say so.

**D1 — The existing alternating band colours ARE the A/B sides, for free.** Verified, not assumed:
`PhaseVelocity.js:236-241` already paints each band `s.n % 2 ? var(--color-cycle-a) :
var(--color-cycle-b)`, with the breakout short-circuited to gold and pulled out of the rotation.
87-01 D3 defines side **A = even array positions** of `strokes`; `buildBands` numbers items
`stroke_num + 1`, so array position 0 → `n = 1` → odd → `--color-cycle-a`. **Side A is blue, side B
is purple, with zero change to the band renderer.** The two tokens were even named `cycle-a` /
`cycle-b` before there were sides.

⚠ This is an alignment between two independently-authored conventions, so it is pinned by AC-4 and
by a render assertion rather than left as a comment. It holds only while `stroke_num` is **dense and
0-based** (it is — 87-01 assigns it `len(strokes)` at append time, the same rule `cycle_num` has
always used). If the backend ever drops a stroke without renumbering, the legend starts lying.

**D2 — The toggle is local to `PhaseReportCard`, persisted globally, and never lifted into
`useTracePrefs`.** That hook is page-owned and deliberately shared with the `/video` route so trace
colours stay in step across surfaces; granularity has no meaning there, and putting it in would
advertise a sharing that does not exist. `PhaseReportCard` already owns exactly this pattern for
`dismissed` — `useState` + hydrate in an effect. Key `swimnetics.swimGranularity`, values
`"cycle"` / `"stroke"`, global (not per-session): a coach who thinks in strokes should stay in
strokes when they open the next swim.
⚠ **Read in an effect, NEVER a lazy initializer** — `localStorage` is absent during SSR and reading
it in render desyncs hydration. The rule is written at the top of `useTracePrefs.js` and this file
already obeys it.

**D3 — Effective mode is `strokes?.length ? pref : "cycle"`, and the fallback is never persisted.**
`strokes` is `null` for butterfly / breaststroke / im / udk (87-01 AC-1) and absent on every session
predating the backfill. Opening one of those with `"stroke"` stored must render exactly today's card
and must not overwrite the coach's preference on the way through.

**D4 — Stroke-level means are re-derived client-side; the stored `session.mean_*` keys are cycle-
level and must never sit under stroke dots.** `CycleCharts` draws a dashed reference line from
`session.mean_dps_m` / `mean_isi_s` / `mean_arm_peak_vel_ms` / `mean_coast_fraction` and prints the
same numbers in its captions. A cycle is two strokes, so `mean_isi_s` and `mean_dps_m` are ~2× the
stroke-level value — the dashed line would sit clean off the top of the dots. 87-01 stores no
stroke-level means, so a new pure `deriveMeans` in `web/lib/strokeStats.js` computes them.
⚠ **Population std (`ddof = 0`)**, matching numpy's `.std()` in `metrics.py:1716-1718` — otherwise
the same caption reads a different CV in the two modes for no reason a coach could ever discover.

**D5 — `CycleCharts` keeps its prop named `cycles` and is handed strokes through it.** Renaming to
`items` would ripple into `CompareCycleCharts` and the legacy no-phases branch, both explicitly out
of scope. The wart is documented at the call site and in the component's docstring so a later reader
does not "fix" it. Same reasoning as `buildBands`, which has passed `phases.kick_bands` through a
`cycles`-shaped parameter since 83-02.

**D6 — One deliberate exception to `PhaseVelocity.js`'s standing DO-NOT-CHANGE: an optional
`itemLabel` used only inside its `aria-label`.** That string reads `coloured one band per cycle
(N bands)`; in stroke mode it would be wrong for exactly the users who cannot see the colours. The
boundary exists to protect that file's **geometry** — 83-01 lost a verify to a prop shadowed inside
`geom`, 83-02 broke a zero-diff AC — and geometry is untouched here. 83-05 took the same posture
when it had to add two `export` keywords to `cycleShape.js`. AC-8 bounds the diff to one parameter
with a `"cycle"` default and one interpolation, and the harness pins the default string.

**D7 — In stroke mode the overlay pack is tinted by side, and its median is replaced by TWO
per-side medians.** This is the phase's actual picture: side A's strokes and side B's strokes laid
on one axis is the only view where a 6% tempo split is *seen* rather than read off a number.
83-05's "all-grey pack" decision was about not **asserting** which stroke is odd — a classifier it
had measured out. Colouring by which arm produced a trace asserts nothing; it labels a structural
fact. Both are opt-in props defaulting off, so cycles and kicks render byte-identically.
⚠ Per-side medians keep 83-05's `MIN_ITEMS = 5` gate **per side** (so ≥10 strokes ≈ ≥5 cycles;
the library median is 7 cycles a lap, so they will usually draw) and stay normalized-only — a
pointwise median needs a common x-grid and seconds mode has none.

**D8 — No warning banner on auto sessions.** 87-01 D2 is explicit: the user saw the r = −0.06
measurement and chose to ship the number marked **only by the existing `auto` chip**. The badge
already reads `N strokes · auto`. Recorded as their call; do not soften it with chrome they declined.
What this plan *does* add is the **definition** of A and B — "the two alternating arms; a
single-axis encoder cannot tell which is left" — as always-visible small print, because the readout
is unreadable without it. A definition is not a warning.

**D9 — The Arm balance readout states magnitude and direction, and passes no verdict.** No "even"
threshold, no good/bad colour, no flag. 83-03's cut classifier is the precedent for not shipping an
unmeasured cutoff, and there is no usual-range baseline for these keys — 87-01 D4 leaves
`phase_metrics.py` untouched precisely because the existing baselines are five *cycle-level* swims
deep. Phrasing is comparative, not declarative: **`Tempo — 6.2% apart · A slower`**.
⚠ Asymmetry is a **percentage**, and the four CVs are ratios: the whole block is **unit-invariant**.
It must not be multiplied by 1.09361 in imperial. Stated so nobody "fixes" it.

**D10 — Stroke mode adds one 8-word line above the Swimming strips: "Usual-range comparisons below
stay per cycle."** 87-01 D4 keeps the strips cycle-level on purpose; a coach who has just switched
the whole section to strokes would otherwise reasonably read the band under `Tempo vs distance` as
a stroke-level range. This is a scope statement about what is being compared, not a verdict, and it
appears only in stroke mode.
</decisions>
