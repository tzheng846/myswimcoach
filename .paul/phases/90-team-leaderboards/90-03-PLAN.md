<objective>
## Goal
Turn 90-02's counted, partitioned data into eight readable boards per stroke: rank, name, value,
swim count, top five with the full order one click away — and prove on screen that flipping to
imperial changes every number and no rank.

## Purpose
This is the phase's actual deliverable. CONTEXT goal 1 is *"a coach can see their squad ordered on
a metric, per stroke, in one glance — the ordering is the deliverable, not the cut."* CONTEXT R7
sharpens it: backstroke has 2 athletes and butterfly 4, so "Top 5" hides nobody on three of the four
boards. The design must not lean on a cut that does not exist.

- `web/app/app/leaderboard/page.js` — the placeholder metric list replaced by 8 boards + the unit toggle
- `scratch/leaderboard_check.mjs` — extended with render checks

<acceptance_criteria>

## AC-1: A board reads as an ordering
```gherkin
Given the freestyle Average speed board on today's library
When it renders
Then it shows rows in the form "1  Max  1.88 m/s  n=5", ranked best-first
And each row names the athlete, their value, and how many swims that value averages
And the board's title is the metric's label from LEADERBOARD_METRICS
```

## AC-2: Top five, with the full order one click away
```gherkin
Given a stroke with more than five ranked athletes
When the board renders
Then exactly five rows are visible and a control reads "Show all 7"
When that control is activated
Then all rows are visible and the control reads "Show top 5"
Given a stroke with five or fewer athletes (butterfly 4, backstroke 2 today)
Then no such control renders at all — the board is already the whole list
```

## AC-3: A missing value is shown, not hidden, and not ranked
```gherkin
Given the breaststroke Split 15–20 m board, where Dane has no value on either of his two eligible
  swims (measured — this is live on real data, not hypothetical)
When the board renders
Then Dane appears at the bottom with a dash in place of a value and no rank number
And a short note distinguishes "no rank" from "last place"
And he is NOT counted in the "Show all N" total of ranked athletes
```

## AC-4: The unit toggle converts every value and reorders nothing
```gherkin
Given the leaderboard with the standing swimnetics.unit preference set to metric
When it is switched to imperial
Then every m/s value becomes a yd/s value multiplied by M_TO_YD, and the "s" lap-time board is
  unchanged (seconds carry no length power)
And the rank column, the row order, and the athlete names are byte-identical between the two
  renders — because rankBoard runs on SI and conversion is applied at the last moment (88-03 D2)
```

## AC-5: The page holds eight boards per stroke and switches cleanly
```gherkin
Given the leaderboard page
When a stroke tab is selected
Then eight boards render for that stroke in catalog order: Average speed, Top speed, Lap time,
  Underwater speed, Split 0–5 m, Split 5–10 m, Split 10–15 m, Split 15–20 m
When a different stroke tab is selected
Then all eight boards rebuild for that stroke and no expanded "show all" state leaks across tabs
```

## AC-6: Lap time is visibly the derived one
```gherkin
Given the Lap time board on today's library
When it renders
Then no athlete's value is 39.0 s
And Max's freestyle lap time reads about 15 s, not about 39 s
```

## AC-7: The harness covers what a render can prove
```gherkin
Given `node scratch/leaderboard_check.mjs`
When it runs
Then it additionally asserts the top-5 cut, the show-all threshold, the unranked-row rendering,
  and — the load-bearing one — that a metric render and an imperial render produce the same
  sequence of athlete names and rank numbers
And it still needs no auth, no network and no dev server
```

## AC-8: Verified on screen by a human
```gherkin
Given the dev server and a signed-in coach
When the leaderboard is opened and exercised
Then the boards match scratch/_lb_expect.py's counts and read correctly
```

<task type="auto">
  <name>Task 1: The board component</name>
  <files>web/components/portal/LeaderboardBoard.js</files>
  <action>
    New client component taking `{ metric, entries, factor, unit }` where `entries` is exactly what
    90-01's `rankBoard` emits and `factor`/`unit` come from `displayUnit(metric.unit, imperial)`.

    Render a card in the portal's existing visual language (`rounded-xl border border-navy/50
    bg-surface`, the same idiom as `TeamPulse`'s `Stat` and `GroupCompare`'s panels — copy the
    classes, do not invent a new card):
    - a header with the metric label and, small and muted, the direction in words ("higher is
      better" / "lower is better") so a coach never has to infer which end is good;
    - up to five ranked rows: rank number in a fixed-width gutter, athlete name, value formatted to
      2 decimals (1 for seconds) followed by the display unit, and `n=K` muted at the end;
    - unranked rows (value null) at the bottom, dimmed, with an em dash where the value goes and no
      rank number;
    - the AC-2 control: rendered only when `ranked.length > 5`. It is a `<button>`, and the label
      flips between "Show all N" and "Show top 5". `N` counts **ranked** entries only (AC-3).
    - one muted line, rendered only when at least one entry is unranked: "— = no swim with this
      measurement, not last place".

    ⚠ Apply `factor` at the point of formatting and nowhere else. Do not scale `entries` before
    sorting, do not recompute a rank from converted values, do not pass a converted value back into
    anything. 88-03's D2 is what makes AC-4's "reorders nothing" structural instead of hoped for.

    ⚠ `expanded` is component-local `useState(false)`. Give the component a `key` that includes the
    stroke at the call site so a tab switch remounts it and collapses the board — that is AC-5's
    "no expanded state leaks across tabs" and it avoids resetting state in an effect
    (`react-hooks/set-state-in-effect` is an error in this repo).

    Avoid: colour-coding rows good/bad. CONTEXT F8 and 87-02's D9 both land in the same place — the
    board states an order, not a verdict, and there is no validated threshold behind a green row.
  </action>
  <verify>node scratch/leaderboard_check.mjs — the new render checks pass</verify>
  <done>AC-1, AC-2, AC-3 satisfied</done>
</task>
