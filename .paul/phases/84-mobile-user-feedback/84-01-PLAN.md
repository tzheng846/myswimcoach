<grounded_facts>
Measured from the tree on 2026-08-29. **These supersede CONTEXT where they disagree.**

### G1 — There is no OTA channel. Everything in Phase 84 needs a build.
`package.json` has no `expo-updates`; `app.json` has no `updates` key; `eas.json` has only
`build`/`submit` profiles and no channels. CONTEXT's open question 2 is answered **no**. The
native/JS split therefore drives *verification cost*, not *shipping order*.

### G2 — The "SVG" is a base64 PNG in an SVG wrapper. There is nothing to vector-rasterize.
```
<svg viewBox="0 0 1028 1028">
  <image width="1004px" height="960px" xlink:href="data:image/png;base64,…">
```
The payload is a **1004×960 RGBA PNG**, colortype 6, 56.4% fully transparent, two inks:
`#7200FF` (403,299 px) and `#FFFFFF` (7,356 px, interior highlight + negative space).
Consequences that bind the implementation:
- **1024 is a 2% upscale** off a 1004 px source. Acceptable, but do not pretend it is lossless.
- The `<image>` is anchored at **x=0, y=0 inside a 1028×1028 viewBox** — 24 px right and 68 px
  bottom margin, zero left/top. Honouring the viewBox puts the mark **off-centre, up and left**.
  Do not render the SVG; decode the payload and compose deliberately.
- **The ink bbox is the entire 1004×960 canvas** (`getbbox() == (0,0,1004,960)`, margins 0/0/0/0).
  The art bleeds to all four edges and has **no built-in padding**. Its aspect is 1.046:1, so it
  cannot be scaled to fill a square without distortion.

### G3 — iOS app icons must not carry alpha; the web precedent does not transfer.
Phase 85's `web/app/icon.png` and `apple-icon.png` are **RGBA with transparent backgrounds**
(alpha-0 is the dominant colour in both). That is correct for a favicon and **illegal for an iOS
app icon** — App Store validation rejects the build. This plan deliberately diverges from the web
asset: opaque, RGB, no alpha channel at all.

### G4 — `sharp` is NOT in the mobile repo.
CONTEXT says it is. `swimnetics-mobile/node_modules` has no `sharp`. It exists at
`myswimcoach/web/node_modules/sharp@0.34.5`. Python **Pillow** is available in the backend repo and
is the simpler tool for a decode-composite-resize job with no SVG rasterization step (G2). Use
Pillow; it also puts the script in the repo that owns the source art, matching the existing
`scratch/_export_marketing_geom.py` / `scratch/_embed_mark.py` pattern.

### G5 — Item 4 has exactly one site and no JS accomplice.
`grep -rn "ScreenOrientation\|orientation\|Landscape" src/` returns **nothing** — no runtime
orientation lock or unlock anywhere in the app. `Info.plist` has **one** `Orientation` key (line 44);
there is no `UISupportedInterfaceOrientations~ipad` variant, and `app.json` sets
`"supportsTablet": false`, so iPad is not a target. CONTEXT's diagnosis is exact and complete: two
`<string>` lines, one file.
</grounded_facts>

  <action>
    Create `scratch/make_app_icons.py` (Python + Pillow), run from the myswimcoach repo root.
    It emits to `scratch/appicon/` — NOT straight into the mobile repo. Task 2 does the copy,
    after the checkpoint.

    Pipeline, in this order:
    1. Read `assets/icon/Swimnetics_icon.svg` as text. Extract the base64 payload with
       `re.search(r'base64,([A-Za-z0-9+/=]+)')`, b64-decode, open with Pillow, convert to RGBA.
       **Do not render the SVG.** Per G2 there are no vector paths, and honouring its viewBox
       would anchor the mark top-left.
    2. Crop to the alpha bounding box (`im.getbbox()`). Per G2 this is currently a no-op — the
       bbox is the full canvas — but it makes the script correct if the mark is ever re-exported
       with margin, which is exactly the drift that would otherwise silently re-centre the icon.
    3. Scale so the art's LONGEST side is 80% of the target edge, preserving aspect
       (`Image.LANCZOS`). At 1024 that is 819 px wide and ~783 px tall, leaving ~102 px of side
       margin — comfortably clear of the iOS superellipse mask.
    4. Composite onto an opaque square RGB canvas of the target size, centred: offsets are
       `((edge - w) // 2, (edge - h) // 2)`. Use `Image.alpha_composite` semantics via
       `canvas.paste(art, offset, art)` so the 56% transparency and the antialiased edges blend
       against the background rather than against black.
    5. **Background = `#FFFFFF`.** Named as a module-level `BG = (255, 255, 255)` constant so the
       checkpoint can flip it in one line. Rationale: the mark's white highlight arc sits INSIDE
       the purple dome and the white gap between dome and tentacles is negative space, so a white
       ground renders the mark exactly as designed. A purple ground erases both. Anything dark
       loses contrast against `#7200FF`.
    6. `.convert('RGB')` before saving — this is what actually strips the alpha channel (AC-2).
       Save with `optimize=True`. Do NOT pass `transparency`.
    7. Emit sizes 1024, 180, 120, each resized independently FROM THE FULL-RESOLUTION SOURCE, not
       downsampled from the 1024 output — one resample per file is sharper at 120 px than two.
    8. Print one line per file: filename, `im.mode`, `im.size`, and `'tRNS' in im.info`.

    Determinism (AC-1): no timestamps, no `Image.new` random fill, fixed `optimize=True`. Pillow's
    PNG writer is deterministic for identical input, so a second run must byte-match.

    Avoid: ImageMagick `convert` — on this Windows box that resolves to NTFS `convert.exe` and will
    silently do something else entirely (CONTEXT item 1 already flags this).
    Avoid: `sharp` — it is not in the mobile repo (G4) and adds a Node dependency for no gain.
  </action>
  <verify>
    `python scratch/make_app_icons.py` twice; then
    `python -c "from PIL import Image;

    Byte-identity across runs: compare `hashlib.sha256` of each file before and after the second run.
  </verify>
