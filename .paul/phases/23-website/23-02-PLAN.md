<objective>
## Goal
Build the authenticated coach portal with iOS-app feature parity: Supabase login, multi-swimmer dashboard, athlete roster, session history (filter/star/rename/notes/delete), and the full report card (all metrics + data quality + time-to-X + interactive velocity chart).

## Purpose
Coaches review and manage everything from a browser — the web counterpart to the iOS app's post-recording experience (recording itself stays on iOS).

## Output
- `/login` + auth-guarded `/app/*` routes
- Dashboard, Athletes, Session History, Report Card pages
- CORS middleware in api.py so the browser can call Railway endpoints
</objective>

## AC-1: Auth gate works
```gherkin
Given an unauthenticated visitor
When they open any /app route
Then they are redirected to /login
And after logging in with a valid coach account they land on the dashboard
And logout returns them to the marketing site
```

## AC-2: Dashboard + roster parity
```gherkin
Given a logged-in coach with athletes and sessions
When they open /app
Then each athlete card shows letter avatar, name, and latest-session key metrics (mean velocity, stroke rate, DPS, date)
And they can add an athlete (name + head_waist_m) via the POST /athletes proxy and edit head_waist_m
```

## AC-3: Session history management
```gherkin
Given an athlete with sessions of multiple stroke types
When the coach opens the session list
Then stroke filter chips appear only for strokes that have sessions
And the coach can star, rename, edit notes, and delete a session
And each change persists via PATCH/DELETE to Railway and survives reload
```

## AC-4: Report card parity
```gherkin
Given a stored breaststroke session
When the coach opens its report card
Then they see the SESSION summary card, all metrics.py session metrics with rating colors, the data quality card, and time-to-X presets (1–25 m, adjusted by head_waist_m)
And an interactive velocity chart with hover cursor, zoom, m/yd toggle, and time markers
```
