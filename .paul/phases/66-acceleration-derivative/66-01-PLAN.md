<objective>
## Goal
Replace the acceleration derivation — currently decimate velocity to ~5 Hz → `np.gradient` →
linear-interpolate back — with a **Savitzky–Golay first derivative at full rate**, so stored and
displayed acceleration is smooth and full-resolution instead of a faceted ~5 Hz reconstruction. Then
re-backfill the existing rows.

## Purpose
The Phase 64-03 acceleration trace looks choppy because the DATA is choppy: a 2.5 Hz-bandwidth
derivative reconstructed by straight-line interpolation between points 0.2 s apart, plus corners
introduced by the forward-only velocity clamp. SG fits a local polynomial and takes its analytic
derivative at every sample — one pass that smooths and differentiates without finite-difference
noise blow-up.

⚠ **Display-only in impact.** `metrics.py` consumes `vel`, not `accel` (no acceleration appears in
`compute_session_metrics`'s signature or any session-metric key), and velocity is untouched. So this
changes ONLY the acceleration trace on the web overlay/chart (64-03) — no metric moves.

## Output
- `acceleration_from_velocity` reimplemented with `scipy.signal.savgol_filter(deriv=1)`.
- The test that pins the OLD algorithm replaced with smoothness + exactness assertions.
- `tools/backfill_acceleration.py` gains a `--recompute` mode (overwrite existing accel).
- Deployed to Railway + all rows re-backfilled from their stored velocity.
</objective>
