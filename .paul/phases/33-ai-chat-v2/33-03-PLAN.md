<objective>
## Goal
Ground the chat's call-to-action in a real drill library. Build ~8 flagship drills, each
tagged with the metric problems it addresses, plus a pure recommender that derives a
session's "problem flags" from its metrics and matches them to drills. Add a
`recommend_drills` tool so the AI ends with a SPECIFIC drill and explains the
data→drill→why chain — never an invented drill. Tag-matching only (semantic RAG is 33-04);
no new dependency.

## Purpose
Per the user, the drill recommendation + "why this drill applies" is the core call-to-action
(PROJECT.md AI coaching value). Today coach.py just asks the model to end with "ONE drill" —
ungrounded. This makes the drill come from a curated, reviewable library matched to the
swimmer's actual metric problems.

## Output
- `drills.py` (new, pure): `DRILLS` library (~8) + a flag taxonomy + `flags_from_session`
  (metrics → active problem flags, thresholds reused from coach.py prose) + `match_drills`.
- `coach.py`: `DRILL_TOOLS` (`recommend_drills`) + a prompt hint and guardrail (only
  recommend drills the tool returns; explain why each fits THIS data).
- `api.py`: `_exec_recommend_drills` (uses the anchor session's metrics) registered in the loop.
- Tests: `tests/test_drills.py` (pure) + a chat integration test.
</objective>

<acceptance_criteria>

## AC-1: Drill recommendation is grounded in the data
```gherkin
Given a session whose metrics show a problem (e.g. low mean_dps_m + low mean_trough_vel_ms)
When the coach asks "what should she work on?" / the model goes to recommend a drill
Then recommend_drills returns drills from the library whose targets match the session's flags
And the answer names a specific library drill and explains why it fits THIS session's numbers
```

## AC-2: No invented drills; honest when nothing is flagged
```gherkin
Given the recommender returns a shortlist (or an empty list when no metric crosses a threshold)
When the model answers
Then it only recommends drills from the returned shortlist (guardrail), never an invented one
And when no problems are flagged, it says the form looks solid rather than forcing a fix
```

## AC-3: Flag derivation is deterministic and threshold-based
```gherkin
Given a session metrics dict
When flags_from_session runs
Then it returns exactly the flags whose thresholds are crossed (reusing coach.py's numbers)
And match_drills ranks drills by how many of the session's flags they target
```
