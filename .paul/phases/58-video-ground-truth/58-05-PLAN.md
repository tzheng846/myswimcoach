<objective>
## Goal
Make a session card identify its session. Today the card shows a bare date, three metrics, and a
stroke abbreviation — for the 19-session corpus that renders as nineteen cards reading
"Aug 5, 2026", indistinguishable from each other.

After this plan every card carries: an auto-generated name when none was typed, the athlete, the
stroke, a weekday-or-date, and — prominently — whether it has been annotated, plus whether it has
video and whether the capture had a quality problem.

## Purpose
Directly unblocks the annotation batch. 57-02's close established four facts about the 19 sessions
that make the current list unusable: they are **a time block on one evening (19:50–20:59), not a
date**; **none has a name**; **none has video**; and one needs discarding and redoing. You cannot
work a batch from a list where every row looks the same and nothing says which ones you have
already done.

**Relationship to 57-03 (annotation queue), stated rather than discovered later:** 57-03's own
summary names "a timestamp-only list will be unusable" as its blocking constraint. This plan solves
that constraint on the list that already exists. After it lands, 57-03 should be re-scoped — the
open question becomes whether a separate queue page is still needed at all, or whether prev/next on
the annotate page is the only remaining piece.

## Output
Two web files. No backend, no schema, no new dependency, no deploy beyond a Vercel push.
</objective>

## AC-1: Every card has a usable title
```gherkin
Given a session with no name (all 19 of the current corpus)
When the sessions list renders
Then the card title reads "{Stroke} · {h:mm AM/PM}" — e.g. "Freestyle · 8:24 PM"
And two sessions recorded 20 minutes apart on the same evening have visibly different titles
Given a session that HAS a name
Then the typed name is shown instead, unchanged
```

## AC-2: The card says whose session it is, and when
```gherkin
Given the default "All athletes" view
When the list renders
Then each card shows the athlete's name
And a recording from the last 7 days shows a weekday ("Wed")
And an older one shows "MM-DD-YY"
And a session whose athlete cannot be resolved omits the name rather than printing a placeholder id
```

## AC-3: Annotated state is prominent and honest
```gherkin
Given a session with a row in session_annotations
When the list renders
Then the card carries a visually prominent "Annotated" marker, distinct from the muted metadata
And its tooltip distinguishes "metrics were recomputed from these marks" from "marks saved, but
    not enough cycle boundaries to recompute"
Given a session with no annotation row
Then no marker appears
```

## AC-4: Video and quality are visible at a glance
```gherkin
Given a session with video_path set
Then the card shows a video indicator
Given a session with >5% magnet dropout, or any implausible cycles, or a non-kick warning
Then the card shows a warning indicator naming the reason in its tooltip
Given a session whose ONLY warning is the always-present kick-reliability one
Then NO warning indicator appears
```

## AC-5: The list is current after annotating
```gherkin
Given the coach opens a session, annotates it, and returns to the sessions list
When they return by link, by browser Back, or by refocusing the tab
Then the "Annotated" marker is present without a manual reload
```

<boundaries>

## DO NOT CHANGE
- `api.py`, `annotations.py`, `metrics.py`, the schema — this plan reads existing columns only.
  `session_annotations` is reachable via RLS, so no endpoint is needed.
- `sessions.name` is never written. The generated title is display-only (user decision): it fixes
  all 19 unnamed sessions immediately, and a name typed later simply overrides it. No backfill, no
  write against production data.
- The Rate / Speed / Dist stat row — swapping Dist for duration was offered and declined.
- The existing top-right ★ + stroke-chip group and its `group-hover:invisible` interaction with the
  star/delete overlay.
- `DataQualityCard.js` — this plan mirrors its thresholds, it does not edit it.
- No git operations. The user runs git.

## SCOPE LIMITS
- Web only. Mobile's `SessionHistoryScreen` is untouched (user decision) — the two card designs
  will diverge, which is accepted.
- No sorting, grouping, searching or filtering changes. The stroke chips and athlete dropdown stay
  exactly as they are.
- No "annotated / not annotated" filter — that is queue behaviour and belongs to a re-scoped 57-03.
- No annotate-from-the-card shortcut, no bulk actions.
- No change to what counts as annotated beyond "a `session_annotations` row exists".
