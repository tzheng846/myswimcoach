<objective>
## Goal
Make an annotation's result reach the coach's report card — for every stroke, by every route back,
and visibly labelled as hand-derived.

Three things, all in one file:
1. **Remove the web stroke gate.** Non-breaststroke sessions currently render "coming soon" instead
   of any metric.
2. **Harden the report card against stale reads.** It refetches on mount only, which is the one
   moment a bfcache restore skips.
3. **Show recompute provenance.** The flag already exists in the data and nothing renders it.

## Purpose
Phases 47, 57 and 58-02 built a tool that produces corrected metrics. If those corrections do not
surface, the tool produces a ground-truth export and nothing the coach can see. This is that last
mile.

**Scope revised 2026-08-07 (user):** the plan originally opened with a diagnosis task for a reported
staleness bug. The user then observed annotations updating correctly. Since **58-02 touched nothing
on the report-card path** — its six files were `annotations.py`, `tests/test_annotations.py`,
`VideoPane.js`, `AnnotationChart.js`, `AnnotationEditor.js` and the *annotate* page — that
improvement cannot be attributed to a code change, which leaves two readings: the bug was
cache-dependent and is currently between appearances, or what looked stale was `initial_phase`
being carried over by design (`api.py:905`). Chasing a bug that is not presenting is slow and
usually concludes nothing, so the diagnosis is replaced by **one check plus a cheap structural fix
that removes the whole class**.

## Output
- The stroke gate removed, reversibly.
- The report card revalidating on `pageshow`/`focus`, not only on mount.
- A provenance marker distinguishing hand-annotated metrics from auto ones.
- `.paul/phases/58-video-ground-truth/58-03-SUMMARY.md`, including a correction to the Phase 54
  record.
</objective>

<task type="auto">
  <name>Task 2: Revalidate on return, and show where the metrics came from</name>
  <files>web/app/app/sessions/[id]/page.js</files>
  <action>
    **First, one observation to record (not a blocking gate).** Annotate a session, save, and return
    via the **browser Back button** specifically — not the link, not a reload. Back is the only
    route that can restore React state from bfcache without re-running the mount effect. Note in the
    SUMMARY whether it showed stale data. This is the last cheap chance to catch the original report
    in the act; the fix below goes in either way.

    **The fix.** `:33-59` fetches in a mount-only `useEffect`, so any return path that does not
    remount the component serves whatever `data` state was left behind.
    - Extract the effect body into a `load()` callback (`useCallback`, keyed on `sessionId`).
    - Call it from the existing mount effect, from a `pageshow` listener when `event.persisted`
      is true, and from a window `focus` listener.
    - `pageshow`/`persisted` is the one that matters and the one `router.refresh()` cannot help
      with: on a bfcache restore the component never re-runs, so nothing React-side fires at all.
    - Guard against overlapping loads with the same `alive` pattern the existing effect uses; do not
      introduce a second copy of the query.

    **Provenance (AC-3).** `metrics_json.data_quality.recomputed_from_annotation` is set by
    `api.py:899` on every successful recompute and **nothing anywhere renders it**. Surface it: a
    small marker near the session summary reading that these metrics come from a hand annotation,
    absent when the flag is absent.

    Look at `DataQualityCard` first — if it already has a natural slot for a provenance row, put it
    there rather than inventing a component.

    Why this is worth doing on its own merits, independent of whether any bug existed: without it
    the coach cannot distinguish "the annotation had no effect" from "the annotation worked and the
    numbers barely moved." That ambiguity is what produced the original report, and it will produce
    the next one too.
  </action>
