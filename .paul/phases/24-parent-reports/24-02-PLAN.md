<objective>
## Goal
Coach-side workflow: store parent contact info on the roster, build report cards
(swimmer multi-select + date range + metric checklist + personal message), and a
send list with per-parent mailto drafts and copy-link actions (real email deferred).

## Purpose
The coach curates what parents see and gets a one-screen mass-send workflow —
the recurring-value feature that justifies the subscription.

## Output
- Parent name/email editing on /app/athletes
- /app/reports builder + generated-reports send list
- web/lib/reportMetrics.js — single source of truth for metric presets
</objective>

## Conventions
- Reads + report INSERT/UPDATE/DELETE via supabase-js (RLS scopes to coach team)
- Token: crypto.randomUUID() generated client-side at insert
- Report URL: `${window.location.origin}/report/${token}`

<acceptance_criteria>

## AC-1: Parent contact on roster
```gherkin
Given the coach opens /app/athletes
When they edit an athlete
Then they can set/update parent name and parent email (validated as email format)
And athletes missing a parent email are visibly flagged on the roster
```

## AC-2: Report builder
```gherkin
Given the coach opens /app/reports
When they select one or more swimmers (select-all available), a date range
  (default: all time), check metrics from the preset list (default: all checked),
  and optionally type a personal message
Then "Generate" creates one reports row per selected swimmer via supabase-js
  (token = crypto.randomUUID(), config_json = {start, end, metrics, message})
And swimmers without parent_email can still be generated but are flagged
```

## AC-3: Send list (mailto + copy, no provider)
```gherkin
Given reports have been generated
When the coach views the send list
Then each row shows swimmer, parent name/email, and actions: View (opens /report/{token}),
  Copy link, and Email draft (mailto: parent_email, subject "{Swimmer}'s Swim Progress
  Report", body = greeting + link)
And a "Copy all links" action yields a paste-ready block (swimmer — parent email — URL per line)
And using Email draft or Copy marks sent_at (timestamp) on that report, shown as "Sent ✓"
And previously generated reports are listed (newest first) with Delete
```
