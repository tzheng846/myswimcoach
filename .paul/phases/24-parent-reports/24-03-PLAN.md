<objective>
## Goal
The parent-facing report card page: a beautiful, mobile-first, interactive page at
/report/{token} that celebrates the swimmer's improvement — animated headline deltas,
touch-friendly trend charts, the coach's personal message, Swimnetics branding.

## Purpose
This page is what lands in a parent's inbox — it is simultaneously the product's
emotional payoff ("look how much my kid improved") and a marketing channel
(every parent sees the brand + a link to swimnetics.com).

## Output
- /report/[token] public route + report components
- Final phase checkpoint (visual + end-to-end)
</objective>

Parents, on phones, non-technical. Tone: warm and celebratory, zero jargon.

Lap Time improvement = went DOWN → "X% faster". Neutral metrics (stroke rate) show
change without good/bad framing.

<acceptance_criteria>

## AC-1: Report renders from token alone
```gherkin
Given a parent opens /report/{token} with no account or login
When the page loads
Then it fetches GET {API}/reports/{token} (plain fetch, no auth) and renders:
  branded header (wave mark + SWIMNETICS), "{Swimmer}'s Progress Report" + period,
  improvement hero cards, a trend chart per selected metric, the coach's message
  (when present), session count, and a footer CTA linking to the marketing site
And an invalid/expired token shows a friendly "report not found" state (no crash)
And a report with <2 sessions shows latest values without delta framing ("first benchmark")
```

## AC-2: Improvement presentation is direction-aware and engaging
```gherkin
Given a metric with direction "higher" improved from first to latest session in range
When the hero card renders
Then it shows a count-up animated percentage with positive (green/primary) styling
And direction "lower" metrics (lap time, consistency CV) invert: a decrease renders
  as positive improvement ("8% faster", "12% more consistent")
And declines render neutrally (muted, no red shaming — e.g. "−3%"), never celebratory
And prefers-reduced-motion disables count-up and chart animations
```

## AC-3: Interactive charts, mobile-first
```gherkin
Given the trend section renders on a 390px viewport
When the parent taps/drags on a chart
Then a cursor readout shows the session date and value
And each chart plots one metric across sessions in the range (dots + line,
  first and latest emphasized) without horizontal page overflow
```

</acceptance_criteria>
