<objective>
## Goal
Data layer for parent report cards: parent contact columns on athletes, a `reports` table with shareable tokens, and a public (no-auth) FastAPI endpoint that serves an assembled report payload by token.

## Purpose
Parents have no accounts — a tokenized URL is the only viable delivery. The token's
payload must be assembled server-side with the service role because RLS blocks anon reads.

## Output
- `supabase/patch_03_parent_reports.sql` (applied by user)
- `GET /reports/{token}` in api.py + tests
</objective>

<acceptance_criteria>

## AC-1: Schema supports parents + reports
```gherkin
Given patch_03 has been run in the Supabase SQL editor
When the coach queries athletes via supabase-js
Then parent_name and parent_email columns exist and are writable under existing RLS
And a reports table exists (token UNIQUE, athlete_id, coach_id, config_json, created_at, sent_at)
And coaches can insert/select/update/delete only their own team's reports (RLS WITH CHECK)
```

## AC-2: Public report payload by token
```gherkin
Given a reports row exists with a valid token and config {start, end, metrics[], message}
When GET /reports/{token} is called with NO Authorization header
Then 200 returns {athlete: {name, parent_name}, period: {start, end}, message,
  metrics: [keys], sessions: [{date, values: {key: number}}...]} for the athlete's
  sessions inside the date range, ordered oldest→newest
And values are pulled from metrics_json->session, cleaned of NaN/inf
```

## AC-3: Invalid token handling
```gherkin
Given no reports row matches the token
When GET /reports/{token} is called
Then 404 is returned (no information leak about whether token format was close)
And a report whose athlete has zero sessions in range returns 200 with sessions: []
```

    Follow schema.sql conventions exactly (header comment, section dividers):
    - ALTER TABLE athletes ADD COLUMN parent_name TEXT, ADD COLUMN parent_email TEXT;
    - CREATE TABLE reports (id UUID PK default gen_random_uuid(), athlete_id UUID NOT NULL
      REFERENCES athletes(id) ON DELETE CASCADE, coach_id UUID REFERENCES coaches(id)
      ON DELETE SET NULL, token TEXT UNIQUE NOT NULL, config_json JSONB NOT NULL,
      created_at TIMESTAMPTZ DEFAULT NOW(), sent_at TIMESTAMPTZ);

      USING/WITH CHECK (athlete_id IN (SELECT id FROM athletes WHERE team_id = current_team_id()))
      — mirror the sessions policy; WITH CHECK is mandatory (patch_01 lesson).
    - Index on reports(token).
    No anon policies — public access goes through the service-role API only.
  </action>

      sessions ordered ascending, values filtered to requested metric keys
    - athlete with no sessions in range → 200, sessions: []
    Avoid: adding auth (defeats the purpose), returning velocity/distance profiles
    (payload bloat; report uses per-session scalars only), exposing coach email/IDs.
