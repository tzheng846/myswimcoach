<objective>
## Goal
Validate whether matrix-profile motif-matching (via `stumpy`: self-join → consensus-stroke
template → `stumpy.match()`) finds plausible stroke-cycle boundaries on freestyle and
butterfly velocity data — strokes where `segment_cycles_trough`'s glide-trough threshold
has nothing to anchor on — and whether it roughly agrees with trough-detection where
trough-detection already works (breaststroke).

## Purpose
`segment_cycles_trough` (metrics.py:66) anchors cycle boundaries on breaststroke's
glide-phase trough — velocity drops near zero between strokes, an unambiguous
segmentation point. Freestyle and butterfly have continuous/near-simultaneous propulsion
with no such dead spot, so the same threshold has nothing reliable to lock onto. That's a
concrete blocker for this phase's freestyle goal — an algorithmic gap, not a
threshold-tuning one. This spike tests a shape-based, stroke-agnostic alternative
("does this window resemble a stroke?" via z-normalized matrix-profile matching, which
doesn't care whether the resemblance includes a trough) before committing engineering
effort toward adopting it, forking by stroke type, or exploring something else.

## Output
- New file `segment_motif_spike.py` — standalone diagnostic at the repo root (matches
  `inspect_cycles.py` / `fetch_sessions.py` flat-file conventions)
- `requirements.txt` — `stumpy` appended
- A visual judgment, recorded in this plan's SUMMARY, on whether motif-matching anchors
  land at plausible stroke boundaries — determines what Plan 16-02 builds
</objective>

        `Q = vel[template_idx : template_idx + m_len]`

        the exact return shape — an array of distance/index pairs)
     f. Convert matches into an anchor list shaped like segment_cycles_trough's output
        (sort by index, build consecutive `{"cycle_num", "start_idx", "end_idx",
        "peak_idx"}` spans) so Task 2 can overlay it using the same plotting helpers
   - Return the anchor list AND the raw matrix-profile distance array `mp[:, 0]`
     (Task 2 plots it)
