# Spike: Wavelet/CWT stroke-rate ridge as a shape-agnostic segmentation candidate

## Context

Plans 16-01 through 16-03 ([16-01-SUMMARY.md](16-01-SUMMARY.md),
[16-02-SUMMARY.md](16-02-SUMMARY.md), [16-03-SUMMARY.md](16-03-SUMMARY.md))
tested four variants of the same family — single-template motif-matching,
chains, Arc Curve/CAC, and multi-length PMP — and all four failed the same
underlying way. Each asks "does this window's *shape* resemble that window's
shape," and that question degenerates whenever (a) stroke shape *drifts*
continuously (regime-locking — 16-01/16-03), (b) the masked region contains a
structurally different motion (dive/pulldown contamination — 16-02), or (c)
the technique's own assumptions don't fit short sessions (CAC — 16-02). PMP's
multi-length search (16-03) even produced real, human-readable structure
(vertical/diagonal conservation bands) — and *still* yielded no
machine-actionable rule, because a heatmap shows where shape-matching *would*
work best, not how to act on that. 16-03-SUMMARY's verdict: close the
shape-matching family; wavelet/CWT is no longer just the front-runner, it's
the only standing candidate.

**The reframe**: instead of "does this shape match that shape," ask "what's
the dominant oscillation frequency *right now*." `CLAUDE.md`'s "Wavelet
notes" already document a concrete recipe — a Morlet CWT (`cmor1.5-1.0`) on
velocity *detrended by a 3-second rolling mean* produces "a clean stroke-rate
ridge" (raw velocity produces dark nodes at stroke boundaries because velocity
genuinely touches near-zero between strokes; detrending removes that
artifact). 16-01-SUMMARY sketched the mechanism from ridge to boundaries:
integrate instantaneous rate into cumulative phase `Φ(t) = ∫rate(t')dt'`,
place a cycle boundary at each integer crossing — the same idea used to
derive heartbeat boundaries from a time-varying heart-rate signal.

This reframe is attractive specifically *because* it inverts each of the
three failure modes above into something the technique handles by
construction:
- **Drift** (the thing that broke every shape-matching variant) is the
  *expected output* of a ridge — a ridge is *defined* as a time-varying
  estimate; tracking it is the whole point, not an edge case to survive.
- **Near-zero dead-spots** (which forced 16-01's trough-based segmentation in
  the first place, and which raw-velocity CWT chokes on) are exactly what the
  documented detrend step removes before the transform runs.
- **Contamination** (dive/pulldown — 16-02's finding): a brief, structurally
  different, *non-periodic* motion has no dominant oscillation to contribute
  — it should show up as a gap or low-power patch in the scalogram, not
  silently corrupt a shape template the way it corrupts self-join matching.

## Hypothesis

A Morlet CWT on the 3-second-detrended velocity signal produces a continuous,
trackable ridge whose instantaneous frequency is the swimmer's stroke rate —
and, critically, this ridge **survives exactly the conditions that broke
every shape-matching variant**: it stays continuous through rate drift
(instead of regime-locking onto one shape) and through the dive/pulldown
phase (instead of being silently corrupted by it). If true, integrating that
ridge's instantaneous rate into cumulative phase and placing boundaries at
integer crossings is a shape-agnostic path to per-cycle segmentation that
generalizes to freestyle/butterfly — strokes with no glide-phase trough for
the current trough-based method to anchor on.

## How to test

### 1. Build the scalogram (apply the documented recipe directly)

For each session: detrend `vel` with a 3-second rolling mean (subtract it —
the documented fix for the near-zero dark-node artifact), run a Morlet CWT
(`cmor1.5-1.0`, via `pywt.cwt` or equivalent already available in the
`mySwimCoach` env) over a scale range covering plausible stroke rates
(breaststroke SPM is already in `compute_session_metrics` output — use that
to bound the scale-to-frequency search range empirically rather than guess),
on the same masked active region (`baseline_end:swim_end`) prior spikes used.
Plot the scalogram (scale/frequency × time, color = wavelet power) — this is
the structural analog of 16-03's motif-heatmap (length × time, color =
conservation), so the two are visually comparable if anyone wants to look
back.

### 2. Extract the ridge and derive boundaries

Take, at each time point, the scale/frequency of maximum power (the ridge);
convert scale → instantaneous stroke rate; integrate into cumulative phase
`Φ(t) = ∫rate(t')dt'`; place a candidate cycle boundary at each integer
crossing of `Φ`.

### 3. Validate the mechanism where ground truth exists (breaststroke)

Run steps 1-2 on the breaststroke sessions already in the 11-session set
(`leo_br_1`, `sid_br_1/2`, `jimmy_br_1`, `connor_br_1..4`), where
`segment_cycles`'s trough-based boundaries are already trusted production
output. Compare: do the ridge-derived boundary times land close to the
trough-based ones, and does the ridge's implied rate track the session's
existing `stroke_rate_spm`? This is the step that turns "the ridge looks
smooth" into "the mechanism reproduces a known-good answer" *before* trusting
it on freestyle/fly, where there is no such ground truth to check against —
mirroring how 16-01/16-02/16-03 always had *some* trusted reference (trough
boundaries, `detect_initial_phase`) to anchor a verdict on real sessions
rather than synthetic ones.

### 4. Look at freestyle/fly with that calibration in hand

Run the same pipeline on `carlos_fr_1`, `carlos_fl_1`, and
`swim_lucas_fl_1_20260515_192933` — the strokes this whole phase exists to
support, and the ones with no trough to anchor on. Having just seen (step 3)
whether the ridge-to-boundary mechanism reproduces a trusted answer on
breaststroke, the question for these three becomes interpretable: does the
ridge look *equally* clean and continuous here, or does it visibly degrade —
and if it degrades, does it degrade the way shape-matching did (fragmenting
at drift/contamination points), or differently?

### 5. Checkpoint (human-eyeball, same convention as 16-01/02/03)

Present, per session: the scalogram with the extracted ridge overlaid, the
ridge-derived boundaries plotted against velocity (and against
`segment_cycles`'s trough boundaries for the breaststroke set), and the
ridge's implied rate-over-time curve. The checkpoint question is **not** a
numeric pass/fail — deliberately deferred, since no one has seen real
freestyle CWT output yet and a tolerance set in advance would be a guess. It
is: *does this look promising enough, on the sessions where we can check it
and the ones where we can't, to invest in turning it into a real
implementation — yes or no?* A "no" here, after three closed shape-matching
spikes, would be a materially different situation than any prior verdict —
worth surfacing explicitly rather than quietly drafting a 16-05.

## Out of scope

- **Setting a numeric go/park bar.** Deferred to the checkpoint itself —
  premature before anyone has seen real freestyle/fly scalogram output (see
  step 5).
- **The PMP "drift toward shorter bands" open question** (16-03-SUMMARY).
  Explicitly dropped, not folded in — re-derivable later from
  `segment_cycles` output in minutes if anyone revisits it; this spike's
  checkpoint stays about the wavelet hypothesis on its own terms.
- **Dive/pulldown re-masking.** Still flagged as a cheap probe in
  16-02/16-03-SUMMARY, now lower priority — only worth it if this spike
  stalls (its main value, derisking a shape-matching fallback, mostly
  evaporates once that family is closed).
- **Building the full segmentation pipeline.** This is a spike to determine
  whether the mechanism *works*, not to ship it — turning "boundaries at
  integer phase crossings" into production code (handling edge effects,
  merging with existing breaststroke logic, wiring into `metrics.py`) is a
  follow-up plan's work, contingent on a "yes" here.
- **Pose/IMU sub-phase work, HMM labeling.** Still correctly parked per
  16-01 — both blocked on data that doesn't yet exist.
