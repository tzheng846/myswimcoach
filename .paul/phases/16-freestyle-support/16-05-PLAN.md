<objective>
## Goal
Make the wavelet/CWT stroke-rate ridge the **production cycle-segmentation engine for
all strokes**, replacing the trough-based call inside `compute_session_metrics`. Trough
detection (`segment_cycles_trough`) stays in `metrics.py` as a never-called reference/
backup. Surface a `segmentation_reliable = False` flag (placeholder quality) through the
session dict and the `/process` `data_quality` object.

## Purpose
Phase 16's research (16-01..16-04) closed three shape-matching approaches and landed a GO
on the wavelet ridge as the only stroke-agnostic segmentation candidate (16-04-SUMMARY).
This ships that direction so freestyle/butterfly produce cycle-level metrics at all —
today they run the breaststroke trough segmenter, which anchors on a glide trough those
strokes don't have. Decision locked with the user (two AskUserQuestion rounds, 2026-06-12):
**"replace all 4 strokes with wavelet; trough is an invisible backup that never runs; no
automatic fallback; accept the breaststroke regression as placeholder quality, tune later."**

## Output
- `metrics.py`: new `segment_cycles_wavelet()` (+ ported helpers/constants) wired as the
  sole segmentation path; `segment_cycles_trough` retained but uncalled; new
  `segmentation_reliable` session key.
- `requirements.txt`: `pywt` added (Railway server-side dependency).
- `api.py`: `segmentation_reliable` added to the `data_quality` payload.
- `tests/test_metrics.py`: re-baselined to the wavelet engine, suite green.
- `CLAUDE.md`: metrics.py description updated (wavelet is now the production segmenter).
</objective>

## Key facts
- `wavelet_spike.find_ridge` re-masks via `detect_phases` internally. The new
  `segment_cycles_wavelet(t, vel)` MUST NOT re-mask — `compute_session_metrics` already
  passes the masked slice `vel[ip_end:swim_end]`. It mirrors `segment_cycles_trough`:
  operate on the passed slice, return slice-relative indices (the existing offset loop
  maps them back), return `None` when no cycles are found.
- `pywt.cwt` cannot run on NaN input and degenerates on flat/near-zero signals
  (`power/col_max` with `col_max==0` → nan in `_track_ridge`). The existing edge-case
  tests feed flat (0.01 m/s) and 5-second signals and must still pass — so the new
  function needs guards that return `None` (→ `cycles=[]`) on too-short or no-power input,
  exactly as `segment_cycles_trough` returns `None` today.
- `metrics.py` is "pure functions, no I/O" — the ported code must carry NO print/plot.
- pywt is already installed in the `mySwimCoach` env (1.8.0); the requirements.txt add is
  for Railway's server-side build.

      operating on the passed slice with NO detect_phases re-masking:
        1. fs = _compute_fs(t); dt = 1/fs.
        2. GUARD: if len(vel) < a safe minimum (enough for the CWT + ≥1 cycle — use the
           same spirit as trough's `< 2` checks; e.g. require at least ~2× the longest
           period in samples, and bail if the detrended signal has negligible power /
           v95 < ~0.01), return None — this is the flat/short edge-case path.
        3. detrend; build scales from [_PERIOD_MIN_S,_PERIOD_MAX_S] via
           pywt.central_frequency (as in find_ridge); pywt.cwt → power = |coeffs|^2.
        4. ridge_idx = _track_ridge(power, freqs_hz); ridge_freq = freqs_hz[ridge_idx].
        5. Integrate phase Φ = cumsum(ridge_freq[:-1] * diff(t)); place a boundary mark at
           each integer crossing (slice-relative index i, NO baseline offset).
        6. return _anchors_from_marks(vel, marks); if it yields < 1 cycle, return None.
    Avoid: calling detect_phases inside (slice is pre-masked); leaving any print/plotly;
    dividing by a zero col_max (guard in step 2 prevents the all-flat case); importing
    from wavelet_spike (port, don't couple — the spike stays a standalone diagnostic).
  </action>
