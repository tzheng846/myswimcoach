<objective>
## Goal
[DU7] Draw the segmenter's cycle boundaries on the session velocity chart so a coach can
see exactly what the wavelet segmenter detected. Boundaries come straight from
`metrics_json.cycles` (`start_idx`/`end_idx` at 100 Hz). Overlay is shown ONLY in the
Advanced view of the session report card, with an honest "experimental" caption (segmentation
is shipped at placeholder quality — `segmentation_reliable=False` always).

## Purpose
Coaches don't currently trust the metrics because they can't see how the swim was cut into
strokes. Exposing the boundaries makes the analysis legible and surfaces obvious mis-segments
(e.g. ridge railing) without dumping more numbers — aligned with the Phase 38/39 "show, don't
overwhelm" direction.

## Output
- `VelocityChart.js` gains a `cycleBoundaries` prop (array of times in seconds) and renders
  faint dashed vertical lines at each boundary, zoom-aware, drawn UNDER the velocity trace.
- `ReportCardScreen.js` computes the boundary times from `metrics.cycles` and passes them to
  the chart only when `view === 'advanced'`, plus a one-line caption.
</objective>

## Key facts (verified this session)
- `metrics.py` cycle dicts: `{cycle_num, peak_idx, start_idx, end_idx}` — start_idx/end_idx are
  INTEGER INDICES into the 100 Hz processed velocity. Consecutive cycles abut
  (end_idx[i] ≈ start_idx[i+1]).
- ReportCardScreen already builds `time = Array.from({length: vel.length}, (_, i) => i/100)` and
  already reuses `cycle.start_idx`/`cycle.end_idx` against `vel.length` in its CSV export
  (lines 170-179) — so `idx/100` is the correct boundary time; no index-space mismatch.
- VelocityChart maps time→x via `px(val) = PAD + ((val - tMin)/tRange)*(W - PAD*2)`, honors a
  `zoomWindow` (tMin/tMax), and draws the zero-line first, then the Polyline.
- The chart is rendered ONCE, below the Simple/Advanced toggle (outside the view conditional),
  so the overlay must be gated by passing `[]` when not in Advanced view.
- Advanced view is itself gated to breaststroke/legacy (`isAnalyticsReady`), so the overlay
  only ever appears for breaststroke/legacy sessions — acceptable.
</context>
