<objective>
## Goal
Give `metrics.py` a per-stroke segmenter seam — a registry plus a `stroke_type` parameter on
`compute_session_metrics` — while routing **every** stroke to the wavelet exactly as today.

**This plan must not change a single number.** Its acceptance is that 59-01's harness returns
byte-identical output.

## Purpose
59-01 measured that no two strokes want the same segmenter: a 20-line peak-pick baseline beats the
shipping wavelet 2× on butterfly (recall 0.84 vs 0.41), while the wavelet wins on freestyle. Acting
on that needs a place to put per-stroke choices; `compute_session_metrics` currently hardcodes
`segment_cycles_wavelet` at one line and never learns which stroke it is looking at.

Separating this from the behavior change is the whole point. Phases 51, 52 and 57 each shipped a
silently wrong number; a structural refactor sharing a diff with a behavior change makes an
unexpected movement unattributable. Here, *any* movement is a bug.

## Output
The seam, its tests, one call site wired, and the docs that describe it. No new file, no new
dependency, no schema change, no deploy-critical behavior change.
</objective>
