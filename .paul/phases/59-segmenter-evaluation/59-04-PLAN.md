<objective>
## Goal
Find a better way to place stroke-cycle boundaries. Build and score a fixed budget of candidates
across four technique families, every one of them **leave-one-session-out**, and produce a ranked
per-stroke table with a recommendation for 59-05.

**Nothing ships to `metrics.py`.** Candidates live in `tools/`; a dead end costs nothing.

## Purpose
`segment_cycles_wavelet` is the thing the annotation effort exists to fix, and it is the one piece
Phase 59 has not touched — it is exactly as 16-05 shipped it. 59-01 built the harness, 59-02 built
the seam, 59-03 fixed the window and the cycle definition. Measured now, in production:

| stroke | old window | new window (shipped) | perfect window |
|---|---|---|---|
| freestyle | 0.186 | **0.280** | 0.458 |
| butterfly | 0.320 | **0.222** | 0.317 |
| breaststroke | 0.473 | **0.167** | 0.232 |

*(entries framing, F1 @±0.15 s, median per session)*

Roughly one boundary in four lands within 150 ms of a human mark. That is the number this plan
exists to move.

## Output
A ranked table, a recommendation, and the reusable candidate code. 59-05 ships the winner.
</objective>

    Every candidate is a callable `(t, vel) -> cycles | None` matching the 59-02 registry contract,
    so a winner is a one-line registry edit in 59-05 and needs no rewrite. Six, across the four

    REFINEMENT (compose with any base — the F1-vs-tolerance curve climbs 0.19→0.74 from ±0.05 to
    ±0.30, which says the events are RIGHT and only the placement is wrong; this is the cheapest
    place a large win can come from):
      R1. wavelet + snap each boundary to the nearest local velocity MINIMUM within ±0.25 cycle
      R2. wavelet + snap to the steepest positive rise (max d(vel)/dt) in the same neighbourhood

    NON-CWT CLASSICAL (genuinely different machinery, not the ridge re-read):
      C1. per-swimmer matched filter — average the velocity segments between human-independent
          coarse boundaries into a template, cross-correlate it back over the swim, take peaks
      C2. `segment_cycles_trough` re-fed the **UNTRIMMED** trace (AC-4). 59-01's 0.00 was a MISFEED:
          it keys on velocity below 0.20×v95 and Phase 57 removed the dead tail those troughs lived
          in. Wrap it for the registry contract (`T_est` from `_estimate_period`).
      C3. autocorrelation period estimate + constant-phase boundary placement — no wavelet anywhere

    LEARNED (user-selected despite 59-01's argument against it at this n):
      L1. a small supervised boundary detector over short velocity windows (logistic regression or a
          shallow 1D CNN on a windowed feature stack), predicting "is this sample an arm entry".
          ⚠ **LOSO IS MANDATORY HERE, NOT OPTIONAL.** 236 marks from ONE swimmer will memorise. If
          the LOSO score is far below in-sample, SAY SO and recommend against shipping it — a
