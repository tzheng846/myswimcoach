<objective>
## Goal
Rebuild the coach dashboard ([web/app/app/page.js](web/app/app/page.js)) from a raw-numbers
athlete grid into a team-health home with four sections — **team pulse** (counts + per-pillar band
distribution), **needs-attention** list, **recent-activity** feed, and a **color-banded roster
grid** — all fed by a single `GET /team/overview` call (shipped in 37-01).

## Purpose
Answers "how is my team doing?" at a glance, the explicit user goal. Today the dashboard does no
aggregation and shows no color; the 37-01 endpoint now returns the whole roster's pillar verdicts,
a band distribution, a needs-attention list, and a recent feed in one payload. This plan is the
view layer for that payload. Bands/colors come from the payload (`ratings.py` source of truth) —
the web never recomputes them.

## Output
- Four new presentational components in `web/components/portal/`.
- Rewritten `web/app/app/page.js` that fetches `/team/overview` once and composes the sections.
- Visually verified against a reachable backend (local uvicorn or the deployed endpoint).
</objective>

<design_spec>
## Payload (from 37-01 — what page.js receives)
```json
{ "athlete_count": 7, "tested_this_week": 4,
  "pillars": [{"key","label","good","ok","needs_work","unknown"}],
  "athletes": [{"athlete_id","name","stroke_type","last_tested","last_session_id",
                "pillars":[{"key","label","band","trend","score","provisional"}]}],
  "recent": [{"athlete_id","name","session_id","date","stroke_type"}],
  "needs_attention": [{"athlete_id","name","reasons":[{"type","pillar?","days?"}]}],
  "rating_colors": {"good","ok","needs_work"} }
```

## Component contracts (presentational — props in, no fetching)
- **TeamPulse({ athleteCount, testedThisWeek, pillars, colors })** — header strip: two stat
  blocks (Athletes / Tested this week) + one chip per pillar showing the band distribution as a
  thin stacked bar (widths ∝ good/ok/needs_work counts, colored from `colors`; `unknown` shown
  muted) plus the label. Pillars with all-zero counts render an empty/“—” bar.
- **NeedsAttention({ items, colors })** — list; each row = Avatar + name + reason chips, links to
  `/app/sessions?athlete=${athlete_id}`. Reason → chip text:
  `needs_work`→“{pillar}” (needs_work color), `declined`→“{pillar} ↓”, `stale`→“{days}d since test”,
  `never_tested`→“Never tested”. Empty `items` → muted “Everyone’s on track.”
- **RecentActivity({ items })** — list; each row = name · stroke · relative date (“2d ago”, “today”),
  links to `/app/sessions/${session_id}`. Empty → muted “No sessions yet.”
- **RosterBandCard({ athlete, colors })** — Avatar + name + “{stroke} · {date|—}”, then four pillar
  band-dots (small colored dot per pillar, color = band color, `unknown`→muted; `title`/aria-label =
  “{label}: {verdict}”). No-session athlete (`pillars: []`) → “No sessions yet”, dimmed. Links to
  `/app/sessions?athlete=${athlete_id}` (unchanged from AthleteCard — keep tight, per phase decision).

## Page (page.js)
"use client"; fetch once with `apiFetch("/team/overview")` (NOT supabase-js — bands come from the
backend). States: loading (“Loading…”), error (muted “Couldn’t load the dashboard.”), empty roster
(existing “No athletes yet…” copy). On success, render in order: TeamPulse → NeedsAttention →
RecentActivity → “Team” heading + roster grid of RosterBandCard
(`grid gap-4 sm:grid-cols-2 lg:grid-cols-3`, as today). Section headings match the existing
`text-sm uppercase tracking-wider text-muted` style; cards use `rounded-xl border border-navy/50
bg-surface`.

## Styling tokens (existing)
ink / subtle / muted / surface / surface-2 / navy / primary / warning / danger. Band/verdict colors
ALWAYS from `payload.rating_colors`, never hard-coded (PillarCards convention).
</design_spec>
