<objective>
## Goal
Make the annotated swim window **authoritative** in the contract and the pipeline, and teach the
contract that one stroke mark is one **arm entry** — so that when the web tool is rebuilt (57-02)
and 19 sessions are annotated, the marks produce correct cycles and nothing outside the window can
contaminate a metric.

Backend + pipeline only. No web, no UI.

## Purpose
19 trustworthy sessions were collected 2026-08-05 (10 free / 4 br / 4 fly / 1 back) — the first
corpus postdating the 2026-06-22 encoder-integrity fixes, and the blocking input to Phase 53 Track
A4 and Phase 16-06. Annotating them under today's contract would bake in three defects: stroke
marks outside the swim window silently become cycles, every mark is assumed to be a whole cycle
(wrong for freestyle and backstroke), and `v95` is computed over the dead tail on every session.
Ordering matters — if the web work (57-02) shipped first, annotations created against the old
contract would have to be redone.

## Output
- `annotations.py` — arm-entry→cycle pairing + swim-window enforcement (pure)
- `metrics.py` — `v95` computed over the swim window, not the full trace (pipeline-wide)
- `api.py` — `stroke_type` threaded onto both annotation paths; `marks_per_cycle` published to clients
- Tests for all three; `CLAUDE.md` updated for the `v95` comparability break
</objective>

## AC-1: Stroke marks outside the swim window are rejected
```gherkin
Given an annotation with stroke_start_s = 2.0 and finish_s = 20.0
When a stroke mark at 21.5 s (in the dead tail) or 1.2 s (before the stroke phase) is submitted
Then validate_annotation returns an error naming the mark index and the bound it violates
And PUT /sessions/{id}/annotations responds 422 with that error in {errors: [...]}
And no cycle is created from the offending mark
```

## AC-2: Freestyle and backstroke marks pair into cycles; fly and breast do not
```gherkin
Given a freestyle session and stroke marks at [2.0, 2.6, 3.2, 3.8, 4.4] (5 arm entries)
When the annotation is converted to compute_session_metrics overrides
Then cycle_bounds contains 2 cycles — boundaries taken at marks 0, 2, 4 — not 4
And the trailing odd arm entry contributes no cycle but remains in stroke_marks_s
And the same marks on a butterfly session yield 4 cycles (today's 1-mark-per-cycle behavior)
```

## AC-3: The k=1 path is byte-identical to today
```gherkin
Given any annotation doc and a stroke_type of butterfly, breaststroke, im, udk, or None
When annotation_to_overrides is called with and without the new stroke_type argument
Then both return exactly the same dict, including the finish_s-appended final boundary
```

## AC-4: v95 is computed over the swim window, pipeline-wide
```gherkin
Given a session whose velocity trace has a long near-zero tail after the swim
When compute_session_metrics runs (auto path — no manual overrides)
Then v95 is computed over vel[baseline_end:swim_end], not the full trace
And per-cycle dead_spot_s and the extract_cycle_peaks detection thresholds reflect the windowed value
And a degenerate or empty window falls back to the full-trace v95 rather than raising
```

## AC-5: stroke_type reaches both annotation endpoints
```gherkin
Given GET and PUT /sessions/{session_id}/annotations
When either handler loads its session row
Then the .select() includes stroke_type
And GET returns marks_per_cycle so the web has a single source of truth for the pairing factor
And PUT passes stroke_type into annotation_to_overrides and returns the derived cycle count
```

<task type="auto">
  <name>Task 1: Arm-entry pairing + swim-window enforcement in annotations.py</name>
  <files>annotations.py, tests/test_annotations.py</files>
  <action>
    **1a. Pairing factor.** Add a module-level map and helper next to `PHASE_KEYS`:

    ```
    MARKS_PER_CYCLE = {"freestyle": 2, "backstroke": 2}
    def marks_per_cycle(stroke_type): -> int   # .get(stroke_type, 1)
    ```

    Rationale to put in the docstring: a mark is one ARM ENTRY (Phase 57 D3). Freestyle and
    backstroke alternate arms, so a cycle spans two entries; butterfly and breaststroke move both
    arms together, so one entry IS one cycle. `im` and `udk` (real values in the mobile STROKES
    list) and unknown/None default to 1 — which is exactly today's behavior.

    **1b. `annotation_to_overrides` gains `stroke_type=None` as a fourth optional parameter.**
    Keep it last and optional so both existing callers (api.py:871, tests) keep working.

    Replace the boundary construction:
    - `k = marks_per_cycle(stroke_type)`
    - `boundaries = marks[0::k]`
    - Append `finish` as a final boundary **only when `k == 1`** and it lies beyond the last
      boundary. Do NOT append it when k > 1.

    WHY the k>1 exception, and do not "simplify" it away: for k=1 a mark is a cycle start and the
    wall legitimately closes the last cycle — that is today's behavior and it is preserved
    byte-for-byte. For k=2 a cycle boundary is a *same-side* arm entry; `finish_s` is a wall touch,
    not an arm entry, so using it as a boundary would manufacture a partial cycle (containing one
    arm entry instead of two) that skews `stroke_rate_spm` and `mean_dps_m` — the exact class of
    silent, plausible-looking corruption this phase exists to remove.

    Everything downstream (the `idx > idxs[-1]` monotonic filter, the `>= 2` sample-span filter)
    stays as-is.

    **1c. `validate_annotation` rejects out-of-window stroke marks.** After the existing per-mark
    ordering check, and only for marks that already passed `check_time`:
    - if `stroke_start_s` is present and mark < it → error
    - if `finish_s` is present and mark > it → error
    Each error names the index and the bound, e.g.
    `stroke_marks_s[7] (21.50 s) is after finish_s (20.00 s)`.
    Enforce each side independently — either boundary may be null.

    NOTE on a hole from CONTEXT.md that this deliberately closes indirectly: `stroke_start_s`
    diverging from the first mark. Rejecting marks before `stroke_start_s` already guarantees
    `marks[0] >= stroke_start_s`, which is the only case that is a genuine phase overlap. A
    remaining *gap* (stroke phase opens slightly before the first arm entry) is real and legal —
    do NOT add a separate relink mechanism or a hard equality check for it. 57-02 surfaces the gap
    as a non-blocking UI hint.

    **DO NOT touch `build_seed`.** D6 stops the web from *applying* the seed; the function and the
    `seed` field in GET stay so no API contract breaks.

    **1d. Tests** in `tests/test_annotations.py` — add a class per concern:
    - pairing: 5 freestyle marks → 2 cycles at boundaries 0/2/4; same marks as butterfly → 4 cycles
    - k=1 equivalence: for each of butterfly/breaststroke/im/udk/None, assert
      `annotation_to_overrides(doc, n, fs, st) == annotation_to_overrides(doc, n, fs)` (AC-3)
    - finish is NOT appended when k=2, IS appended when k=1
    - out-of-window rejection: before stroke_start, after finish, both bounds null → no error
    - a mark exactly ON a boundary is accepted (inclusive)
  </action>
  <verify>`pytest tests/test_annotations.py -q` green; new tests fail if the k=2 finish-append is reintroduced (mutation-check it by hand once, then revert)</verify>
  <done>AC-1, AC-2, AC-3 satisfied</done>
</task>
