<objective>
## Goal
Rebuild the annotate page so 19 sessions and ~500 arm-entry marks are tractable in one sitting, and
so the phase model states plainly what it is: every marker is a START, it opens one interval and
closes the previous one, and two of the five move no number at all.

Web only. The contract it sits on shipped in 57-01.

## Purpose
The Phase-47 page was built and verified at n≈1. At n=19 its defaults actively fight the work: it
preloads segmenter output as if it were ground truth (circular — the segmenter is what 16-06 exists
to evaluate), it renders the full 39 s trace so the swim occupies half the width at ~18 px/s, it
shows "Dive 1.31 s" as a bare number that reads like a duration, and a misclick can only be undone
by hunting for a chip. Every one of those costs multiplies by 19.

## Output
- Blank-start editor with an undo stack and per-mark drag/nudge
- Chart that fits the annotated swim window and trims the dead tail, front deliberately kept
- Phase panel that names intervals, spans, and metric impact explicitly
- Live marks→cycles readout driven by `marks_per_cycle` from the API
</objective>

<task type="auto">
  <name>Task 1: Window-fit chart with draggable marks</name>
  <files>web/components/portal/AnnotationChart.js</files>
  <action>
    **1a. Fit the visible range by SLICING THE DATA, not by setting an XAxis domain.**
    Add a `viewRange` prop `[lo, hi] | null` and build the `data` array only from points whose `t`
    falls inside it. Do NOT drive this with `XAxis domain` + `allowDataOverflow` — the existing
    `<Brush>` also controls the visible domain, and the two fight each other. Slicing leaves the
    Brush operating naturally inside the fitted range, and click coordinates stay correct because
    every point already carries its absolute `t`.

    Keep `MAX_POINTS` decimation, but compute the step from the SLICED length — that is where the
    precision win comes from: the same 2000 points spread over 21 s instead of 39 s.

    **1b. Shade the phase intervals.** Render a recharts `ReferenceArea` between each pair of
    consecutive non-null phase markers, low opacity, using the opening phase's colour. This is what
    makes "these phases do not overlap" visible rather than asserted — the shaded bands tile the
    axis with no gaps and no overlaps by construction.

    **1c. Drag-to-move.** On `onMouseDown`, hit-test the cursor's data-x against every phase marker
    and stroke mark; grab the nearest one within a tolerance of 1% of the visible span. Track the
    dragged item in state, update its time on `onMouseMove`, commit on `onMouseUp` / `onMouseLeave`
    via a new `onMarkDrag(kind, index, newTime)` prop. While dragging, suppress the click handler so
    a drag never also places a new mark.

    Set `cursor: grab` when hovering within tolerance of an existing mark so the affordance is
    discoverable — it is invisible otherwise.

    **1d. Selected-mark highlight.** Accept a `selected` prop (`{kind, index} | null`) and render
    that mark thicker/brighter so keyboard nudging (Task 3) has a visible target.

    Avoid: re-deriving marks in this component. It stays presentational — all annotation state lives
    in the page, which is the existing convention and the reason this file is safe to change.
  </action>

<task type="auto">
  <name>Task 2: Phase panel that states intervals, impact, and cycle count</name>
  <files>web/components/portal/AnnotationEditor.js</files>
  <action>
    **2a. Rewrite the Phases block as intervals.** For each of the five markers show: the label, the
    START time, the span it covers (`start → the next placed marker`, or `→ end of swim` for
    finish), and its duration. An unplaced marker shows "not marked" in muted text — visibly
    different from a placed one, so a partial draft never looks finished.

    Add a one-line header stating the model plainly: each marker is the START of its phase and the
    END of the previous one, so the phases tile the swim and cannot overlap. This is the user's
    explicit request — the invariant has always held in `validate_annotation`; it has never been
    said out loud.

    **2b. Mark what moves a number and what does not.** Dive, Stroke and Finish drive
    `baseline_end_idx` / `ip_end_idx` / `swim_end_idx`. UW kick and Breakout are recorded for the
    16-06 export and feed nothing (`api.py:896` carries `initial_phase` over from the auto result
    unchanged). Render that distinction as a small persistent tag on each row — not a tooltip, not a
    footnote. Two of five clicks moving no number is exactly the kind of fact that should not need
    discovering.

    **2c. Caption Dive as a lower bound.** Under the Dive row, when a time is placed: t=0 is the
    race-start blare, but the first buffered sample lags it by an unmeasured 170–400 ms (BLE write
    round trip + the firmware's variable warmup discard, `ESP_32_V5.ino:383-392`). State that the
    figure is a LOWER BOUND on reaction time and is not a calibrated measurement. Do not compute or
    display a `reaction_time_s` — D4.

    **2d. Cycle readout.** Accept `marksPerCycle` and render, above the mark chips:
    `"{n} marks → {cycles} cycles"` plus the convention in force ("freestyle: 1 mark = 1 arm entry,
    2 per cycle"). Derive cycles exactly as `annotations.annotation_to_overrides` does — boundaries
    at `marks[0::k]`, and `finish_s` closes the last cycle ONLY when k === 1. Getting this wrong
    makes the readout lie about what the server will build, which is worse than no readout.

    When `k > 1` and the mark count leaves a trailing unpaired arm entry, say so explicitly
    ("last arm entry unpaired — no cycle"). It is correct behaviour, but silence would read as a
    lost mark.

    **2e. Controls.** Add "Undo" (disabled when the stack is empty, showing what it will revert) and
    "Discard saved annotation" (destructive styling, confirm first, calls the `onDiscard` prop).
    Replace "Reset to auto" — under D6 the seed is no longer applied, so a button that re-applies it
    contradicts the whole point.
  </action>
  <verify>`npm run build` exits 0; a freestyle session with 18 marks reads "18 marks → 9 cycles"; the same count on butterfly reads 17</verify>
  <done>AC-3, AC-5, AC-7 (panel half) satisfied</done>

<task type="auto">
  <name>Task 3: Page wiring — blank start, undo stack, keyboard nudge, view state</name>
  <files>web/app/app/annotate/[id]/page.js</files>
  <action>
    **3a. Blank start (D6).** Change the load path from `annRes.annotation ?? annRes.seed` to
    `annRes.annotation` only. A session with no saved annotation initialises to empty phases and no
    marks. Keep reading `annRes.seed` off the response — it stays in the API contract and removing
    the field would break it for no gain — but never apply it to editor state. Update `savedMsg` so
    a blank load says so rather than claiming an auto-seeded draft.

    **3b. View state.** Hold `viewMode` = `"fit" | "full"`, default `"fit"`. Compute `viewRange`:
    `finish_s` present → `[0, finish_s + max(1, 0.05 × finish_s)]`; `finish_s` absent → `null` (full
    trace, because there is nothing to fit to yet — the blank-start consequence). `"full"` always
    yields `null`. **The lower bound is 0, never `stroke_start`** — the leading region is the
    reaction-time measurement and must stay on screen (D4, and the user's original request).

    **3c. Undo stack.** A capped array (50) of `{phases, strokeMarks}` snapshots pushed before every
    mutation — placement, drag, nudge, chip delete, clear-all. `undo()` pops and restores. Keep it
    in a ref, not state, except for the depth counter the button needs; snapshotting into state on
    every mark would re-render the chart on every click at 500 marks.

    **3d. Keyboard.** Selection state `{kind, index} | null`, set by clicking an existing mark.
    Arrow left/right nudge the selected mark by one sample (`1 / fsHz`), shift+arrow by ten.
    Backspace/Delete removes it. `Ctrl/Cmd+Z` undoes. Attach on the page, and ignore events whose
    target is an input so typing is never hijacked.

    **3e. Out-of-window guard (AC-6).** In `handleChartClick` for the stroke tool, reject a click
    outside `[stroke_start_s, finish_s]` when those are placed — set an inline message instead of
    adding the mark. This mirrors 57-01's server rule so the coach never places a mark that the save
    will refuse. Keep rendering server 422 strings (`e.body?.detail?.errors`) — the existing handler
    already does this correctly; the client guard is belt-and-braces, not a replacement.

    **3f. Discard.** `onDiscard` → `apiFetch(..., {method: "DELETE"})`, then reset editor state to
    blank and report whether `metrics_restored` came back true. This is the route for the 20:24
    freestyle session, which carries an old-convention annotation the user decided to redo from
    scratch.

    **3g. Save response.** Surface `cycles_derived` and `marks_per_cycle` from the PUT response in
    the saved message ("Saved — 9 cycles recomputed"). A mismatch against the pre-save readout is
    the signal that `stroke_type` is wrong, which is unfixable through the API.
  </action>
