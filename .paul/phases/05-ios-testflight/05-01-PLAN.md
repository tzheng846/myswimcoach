## Goal
Get a blank "Hello Swimnetics" iOS app onto TestFlight. No features. The sole purpose is to prove the EAS Build + provisioning + TestFlight pipeline works before any feature code is written.

## Purpose
The previous Expo crash was on a different app with restricted entitlements (screen tracking). This plan validates that the BLE-capable bare workflow + EAS Build path works cleanly for Tony's setup. Catching submission issues on a blank app is far cheaper than catching them after BLE + recording code is written.

- `mobile/app.json` — bundle ID, Bluetooth permission strings, Expo/EAS config
- `mobile/eas.json` — preview (TestFlight) and production build profiles
- A live TestFlight build installable on Tony's iPhone

<task type="auto">
  <name>Task 1: Configure app.json and create eas.json</name>
  <files>mobile/app.json, mobile/eas.json</files>
  <action>
    **mobile/app.json** — overwrite the generated file entirely with:
    ```json
    {
      "expo": {
        "name": "Swimnetics",
        "slug": "swimnetics",
        "version": "1.0.0",
        "orientation": "portrait",
        "userInterfaceStyle": "light",
        "ios": {
          "supportsTablet": true,
          "bundleIdentifier": "com.swimnetics.app",
          "infoPlist": {
            "NSBluetoothAlwaysUsageDescription": "Swimnetics uses Bluetooth to connect to SwimLogger for swim recording.",
            "NSBluetoothPeripheralUsageDescription": "Swimnetics uses Bluetooth to connect to SwimLogger for swim recording."
          }
        },
        "extra": {
          "eas": {
            "projectId": "REPLACE_AFTER_EAS_INIT"
          }
        }
      }
    }
    ```

    Note: splash and icon fields are omitted intentionally — the bare template
    generates default assets; adding them now would require asset files that
    don't exist yet. Expo will warn but build will succeed.

    **mobile/eas.json** — create this file (it does not exist after scaffolding):
    ```json
    {
      "cli": {
        "version": ">= 12.0.0"
      },
      "build": {
        "preview": {
          "distribution": "store",
          "ios": {
            "resourceClass": "m-medium"
          }
        },
        "production": {
          "distribution": "store",
          "ios": {
            "resourceClass": "m-medium"
          }
        }
      }
    }
    ```

    `distribution: "store"` routes the build through App Store Connect → TestFlight.
    `resourceClass: "m-medium"` uses Apple Silicon build workers (faster, no extra cost).

    Avoid: modifying mobile/ios/ directly — EAS Build handles native config via app.json.
    Avoid: adding `submit` section to eas.json — manual submit via App Store Connect is
    simpler for the first build until eas submit credentials are configured.
  </action>
  <verify>
    python -c "import json; d=json.load(open('mobile/app.json')); assert d['expo']['ios']['bundleIdentifier']=='com.swimnetics.app'; print('app.json ok')"
    python -c "import json; d=json.load(open('mobile/eas.json')); assert d['build']['preview']['distribution']=='store'; print('eas.json ok')"
  </verify>
  <done>AC-1 precondition: app.json + eas.json correctly configured for App Store distribution</done>

<task type="checkpoint:human-action" gate="blocking">
  <action>Run EAS Build and submit to TestFlight</action>
  <instructions>
    Run these commands from inside the mobile/ directory:

    1. Install dependencies (if not done already):
       cd mobile
       npm install

    2. Log in to EAS (one-time, uses your Expo account):
       eas login

    3. Link project to EAS (generates the projectId for app.json):
       eas init
       → Copy the generated projectId into mobile/app.json
         under extra.eas.projectId, replacing "REPLACE_AFTER_EAS_INIT"

    4. Start the build (this runs on Expo's Mac servers — takes 15–30 min):
       eas build -p ios --profile preview

       EAS will ask:
       - "Generate a new Apple Distribution Certificate?" → Yes
       - "Generate a new Apple Provisioning Profile?" → Yes
       EAS handles all signing automatically using your Apple Developer account.

    5. When the build finishes, EAS prints a download URL.
       Upload the .ipa to App Store Connect manually:
       → Go to appstoreconnect.apple.com
       → My Apps → (+) New App → create "Swimnetics" (bundle ID: com.swimnetics.app)
       → TestFlight tab → Upload a Build → use Transporter app or
         eas submit -p ios --latest (if you want EAS to handle upload)

    6. In App Store Connect → TestFlight → Internal Testing:
       → Add the build to internal testing
       → Add yourself as an internal tester
       → Accept the TestFlight invite on your iPhone

    Note: App Store Connect app creation requires selecting a Primary Language
    and Category — use "Sports" and English.
  </instructions>
  <verification>TestFlight app on iPhone shows "Swimnetics" in available builds</verification>
  <resume-signal>Type "submitted" when the build appears in TestFlight</resume-signal>
</task>
