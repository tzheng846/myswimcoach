<objective>
## Goal
Ship the **underwater dolphin-kick detector** + the **seven kick metrics** that ride on it
(`kick_count`, `kick_tempo`, `kick_consistency`, `dist_per_kick`, `per_kick_decay`,
`first_kick_impulse`, `uw_ivv`) — Phase 75 Step 2's high-tier underwater increment. All seven
flip from `planned` to `implemented` in the `phase_metrics` registry.

## Purpose
The underwater phase currently reports only the four window scalars 75-02 shipped
(duration / distance / avg-speed / surface-ratio) plus the breaststroke pulldown. The
coach's own underwater vocabulary — "how many kicks, how far per kick, are they even,
are the last kicks dying" — is exactly the 🔶 heavy extraction CONTEXT.md named. On a 1-D
axial trace each **propulsive downkick is a velocity surge**, so peak-counting the
underwater window yields all seven. Per D7 these **display, not grade** (dolphin kicks have
zero annotated ground truth); validation is by eyeball on real database traces.

## Output
- `metrics.detect_underwater_kicks(...)` — new signal-processing detector (metrics.py's home).
- Seven `_compute_kick_*` functions + one shared `_kick_analysis(ctx)` helper in phase_metrics.py;
  the seven REGISTRY specs flipped to `implemented`.
- `tools/plot_kicks.py` — read-only DB harness rendering each underwater segment with its
  detected kicks marked, for the human-verify checkpoint.
- New tests; suite stays green (355 → 355 + new).
</objective>

Resolved with the user at plan time (2026-08-19), plus decisions inherited from the phase:

- **D-scope: all 7 kick metrics in this one plan** (user). They share ONE detector; the
  metrics are trivial arithmetic on its peak list. Splitting per D12's literal "one at a
  time" would ship a detector with one metric then six near-empty plans. 75-02 precedent:
  4 metrics in one plan.
- **D-ivv: `uw_ivv` = window std/mean** (user) — `np.std(v)/np.mean(v)` over the underwater
  window. **Detector-INDEPENDENT**: it needs only the window, so it computes even on
  sessions where kick peaks are unreliable. Matches the taxonomy's "oscillation amplitude
  vs mean" wording.
- **D-dpk: `dist_per_kick` numerator = total underwater distance** (user) —
  `uw_distance / kick_count`, not a glide-excluded sub-window. Simple, matches the 75-02
  window metrics, racing-meaningful. Caveat (documented, not fixed): a long push-off glide
  inflates it.
- **D-data: eyeball validation reads the DATABASE, never the local raw CSVs** (user, explicit:

  these stored profiles.
- **D-gate: kicks are for the dolphin-kick strokes; breaststroke → None.** `_kick_analysis`

<metric_definitions>
Reference for Task 2. `_kick_analysis(ctx)` computes ONCE per call and returns
`{peaks, troughs, peak_vels, intervals_s, i0, i1, uw_dist}` or **None** when: stroke is
breaststroke, or `_uw_window(ctx)` is None. `peaks`/`troughs` are full-trace sample indices
inside the window. Each metric guards on the peak count and returns None below its floor.

| key | formula | None when | unit |
|---|---|---|---|
| `kick_count` | `len(peaks)` | window absent / breast | count |
| `kick_tempo` | `1 / median(intervals_s)` | < 2 peaks | kicks/s |
| `kick_consistency` | `std(intervals_s) / mean(intervals_s)` (CV) | < 3 peaks (need ≥2 intervals) | ratio |
| `dist_per_kick` | `uw_dist / kick_count` | < 1 peak | m |
| `per_kick_decay` | `(peak_vels[-1] − peak_vels[0]) / peak_vels[0] × 100` (signed; negative = fading) | < 2 peaks | % |
| `first_kick_impulse` | `peak_vels[0] − min(vel from i0 to peaks[0])` (Δv, entry-trough → first downkick) | < 1 peak | m/s |
| `uw_ivv` | `std(vel[i0:i1]) / mean(vel[i0:i1])` — **does not use `peaks`** | window absent | ratio |

`uw_ivv` computes whenever the window exists, even if the detector finds no clean peaks.
</metric_definitions>
