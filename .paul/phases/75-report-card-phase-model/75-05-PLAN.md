<objective>
## Goal
Ship the first visible surface for the race-phase report card (Phase 75 Step 3): a **new
`/app/sessions/[id]/phases` route** in the coach portal that renders `metrics_json.phases` in the
visual language settled in the v3 concept mockup —

- a **deterministic alert line** (count of metrics outside his usual, broken down by valence:
  worse / changed-unclear / better), each flag **coach-dismissable**;
- a left-to-right **phase timeline** (Dive/Push-off | Underwater | Swim) with the breakout marked;
- a phase-tinted **velocity line** (the hero);
- per phase: the phase's **inset chart on top, full width**, then its metrics in **two columns**,
  each metric a **1D usual-range strip** (shaded band + median tick + today dot), colored by
  **direction-of-good** (green better / red worse / grey changed-but-unclear);
- **almost no always-on prose** — every description + comparison lives in a **hover overlay** that
  dims the page.

Baseline = the athlete's **last 5 same-stroke swims**; "usual range" = **median ± 1.5·MAD** (robust
for n=5). Charts are limited to **line / dot-line / 1D strip**; every magnitude axis starts at **0**.

## Purpose
Nothing from Phases 75–79 is visible in any UI yet (STATE item 8). This turns the computed
`phases` object (Start + Underwater implemented & backfilled) into a coach-facing card on the
settled doctrine, **helping the coach rather than replacing them**: objective comparisons, never
verdict prose; color shows good/bad only where a metric has an established direction of good, and
stays neutral where "better" is a coaching call; and the coach can dismiss any flag they disagree
with.

## Output
- `web/lib/phaseBaseline.js` — last-5 same-stroke baseline (median, MAD, band) + pure reducer.
- `web/lib/phaseValence.js` — `DIRECTION_OF_GOOD` map + pure `flagVerdict()` (in-range / good / bad /
  neutral).
- `web/components/portal/phases/{RangeStrip,HoverExplain,PhaseTimeline,PhaseVelocity,AlertSummary,PhaseReportCard}.js`.
- `web/app/app/sessions/[id]/phases/page.js` — the route.
- One nav link added to `web/app/app/sessions/[id]/page.js`.
- `.paul/phases/75-report-card-phase-model/75-05-SUMMARY.md`.

### One metric row — the 1D usual-range strip (replaces the old paired bars)
```
 label (dotted → hover)        1D strip on a 0-based scale          value + status
 ┌──────────────────┐  ┌──────────────────────────────┐  ┌─────────────────────┐
 │ Distance per kick│  │ 0 ────[▓▓▓|▓▓▓]────────●──max │  │ 1.30 m   ↓ worse  × │
 │              ⓘ   │  │        └usual┘  └med  └today │  │        (red)        │
 └──────────────────┘  └──────────────────────────────┘  └─────────────────────┘
   ▭ band  = his usual range (median ± 1.5·MAD of last 5)
   |  med  = his median
   ● today = this swim; sits OUTSIDE the band when flagged, colored by valence
   in-range → dot rests inside the band, neutral color, status "in range" (quiet)
```

### Valence — color = direction of good, NOT direction of change
```
                     value ABOVE usual band     value BELOW usual band
 good = "up"   ....   ● green  "↑ better"    ●  red   "↓ worse"
 good = "down" ....   ●  red   "↑ worse"     ● green  "↓ better"
 good="neutral"....   ● grey   "↑ changed"   ● grey   "↓ changed"     ← we don't know; don't judge
 in range      ....   (no color, no arrow, "in range")
```
Arrow always shows *which way it moved*; color+word show *whether that's good*. Metrics whose
"better" depends on the race plan are `neutral` — flagged (it changed) but never green/red.

### Significance rule (how a flag is decided)
`flagged = value < band.lo || value > band.hi`, where `band = [median − K·sMAD, median + K·sMAD]`,
`sMAD = 1.4826·MAD` (MAD scaled to be σ-comparable), **K = 1.5** (documented, tunable). MAD/median
(not mean/SD) because n=5 makes SD noisy and one odd swim shouldn't move the band. When **n < 2**
priors: no band → every metric renders as "baseline building (n/5)", nothing flagged.

### `DIRECTION_OF_GOOD` (keyed by phase_metrics REGISTRY keys) — a REVIEWABLE judgment table
> ⚠ This map is the ONE place the tool asserts good/bad. It is direction-of-change coloring, **not**
> an absolute/normative threshold — doctrine's "no national/age thresholds" still holds. It is a
> deliberate, user-approved (2026-08-25) evolution of the old "no-valence" display rule. Keep it as
> plain data so a coach can correct it. Only **start + underwater** render this slice; swim/whole
> entries are pre-filled for when those metrics ship.
```
start:       peak_vel:up   time_to_peak_vel:down   max_accel:up   dive_duration:neutral
             glide_duration:neutral  glide_distance:neutral  glide_avg_speed:up
             glide_decel:down  break_into_kick_vel:neutral  reaction_time:down
underwater:  uw_duration:neutral  uw_distance:neutral  uw_avg_speed:up  uw_surface_ratio:up
             kick_count:neutral  dist_per_kick:up  kick_tempo:neutral  kick_consistency:down
             uw_ivv:down  per_kick_decay:up  first_kick_impulse:up
             pulldown_peak_vel:up  pulldown_duration:neutral
swim:        ivv:down  breakout_vel:up  breakout_vel_loss:down  breakout_vs_steady:neutral
             splits:up  sr_dps_coupling:neutral  dead_spot_timing:neutral
             accel_asymmetry:neutral  breathing_dip:down
whole:       phase_time_budget:neutral  phase_dist_budget:neutral  vel_envelope:neutral
             jerk_smoothness:down
```
Any key absent from the map → treat as `neutral` (safe default).

## AC-1: Baseline engine — last-5 same-stroke, robust band
```gherkin
Given a session with athlete_id A, stroke_type S, created_at T
When phaseBaseline(A, S, T) runs
Then it fetches the ≤5 most recent sessions where athlete_id=A AND stroke_type=S AND created_at<T,
  reads each metrics_json.phases, and returns a lookup keyed "<phase>.<key>" holding
  { median, mad, sMAD, band:[median-1.5*sMAD, median+1.5*sMAD], mean, sd, n } over non-null values
And when fewer than 2 priors exist, entries report n<2 and band:null (callers show "building"),
  never crashing or inventing a band
```

## AC-2: Valence engine — deterministic flag + direction-of-good
```gherkin
Given a metric value, its baseline band, and its DIRECTION_OF_GOOD entry
When flagVerdict(value, band, good) runs
Then it returns {flagged, direction:"above"|"below"|null, valence:"good"|"bad"|"neutral"|null}
  where flagged = value outside band; valence = good/bad by combining direction with `good`
  ("up"→above is good; "down"→below is good), and valence="neutral" whenever good="neutral"
And an in-range value returns {flagged:false, valence:null} (renders quiet "in range")
And a missing DIRECTION_OF_GOOD key defaults to "neutral" (never throws, never falsely judges)
```

## AC-3: /phases renders the surface in the v3 visual language
```gherkin
Given a stored session whose metrics_json.phases has Start + Underwater values
When the coach opens /app/sessions/{id}/phases
Then the page shows, top to bottom: a one-line legend; a deterministic ALERT line (count + valence
  breakdown chips "N worse / N changed / N better", zero-chips omitted, "× each to dismiss"); a
  left→right phase timeline with a Surfaced mark and distance/time toggle; a phase-tinted velocity
  line with phase labels pinned to the bottom axis (no overlap); and per phase (Dive/Push-off,
  Underwater) the inset chart FULL-WIDTH ON TOP then its metrics in TWO columns
And each metric row is a 1D usual-range strip (shaded band + median tick + today dot on a 0-based
  scale) with value + status to the right; flagged metrics are colored by valence (green/red/grey)
  with an arrow + word; in-range metrics are quiet ("in range")
And no metric description or comparison is shown as always-on text — it appears only in a hover
  overlay that dims the page, reachable from the dotted label (and the hot timeline segment)
And every value axis / strip scale starts at 0; charts are line / dot-line / 1D strip only
And section titles are terse ("Race phases", "Velocity timeline", "Dive / Push-off", "Underwater",
  "Swimming"); Swim + Whole metrics (planned) render as "coming soon", not empty strips
And a nav link "Race phases ›" appears in the existing session page header
```

## AC-4: Coach control + empty/degraded states
```gherkin
Given a flagged metric
When the coach clicks its × dismiss
Then the flag clears (row → neutral), the ALERT count and valence chips decrement live, and the
  choice persists across reload for this session (localStorage this slice); an "undo"/"restore"
  affordance is available
Given a session with no usable baseline (new athlete / <2 priors)
Then timeline + velocity still render, and strips show today's dot with "baseline building (n/5)"
  and no band — the screen is never empty, nothing is flagged
Given a metric with value null this swim (e.g. pulldown_* on freestyle, or an unusable window)
Then that row reads "not measured this swim", not a zero strip
```
