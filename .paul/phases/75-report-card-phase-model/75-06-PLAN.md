## Goal

Implement the 12 remaining race-phase registry metrics (8 Swim + 4 Whole) and render them on the
primary session report card at `/app/sessions/[id]`, replacing the Whole-race `<ComingSoon>` stub and
giving the Swimming section its first registry content. Per-cycle metrics read the coach's annotated
cycles when they exist and fall back to auto segmentation otherwise.

## Purpose

Phase 75's Step-2 metric work is the last unbuilt piece of the race-phase model (STATE item 7). Start
(75-04) and Underwater (75-02/75-03) ship; Swim and Whole are the two panels a coach opens and finds
empty. This closes the metric registry and completes the report card's four-phase spine.

<planning_decisions>
Six decisions were locked in `/paul:discuss` (D1–D6, see 75-06-CONTEXT.md). Five open questions that
CONTEXT deferred to planning are resolved here:

**D7 — Vector metrics become N SCALAR REGISTRY SPECS, not list-valued specs.** CONTEXT open question 1.
Decisive reason: `web/lib/phaseBaseline.js` builds an athlete's usual range by reading the SAME key out
of past sessions' `metrics_json.phases`. A list-valued metric would force baseline lookup to index into
an array whose length varies per session (a 15 m swim has no 25 m split), so element alignment would
silently break across history. Scalar keys are independently `None`-able and need zero engine change.
- `splits` → `splits_5m`, `splits_10m`, `splits_15m`, `splits_20m`, `splits_25m`
- `phase_time_budget` → `phase_time_budget_start`, `_underwater`, `_swim`
- `phase_dist_budget` → `phase_dist_budget_start`, `_underwater`, `_swim`
- `vel_envelope` → `vel_envelope_start`, `_underwater`, `_swim`, `_overall`
The four original vector keys are REMOVED from `REGISTRY`. Safe: all four are `status="planned"` today,
so no stored session carries a value for them.

**D8 — Degraded state = a `provisional` boolean on the emitted metric dict.** CONTEXT open question 2.
`MetricSpec` gains `needs_cycles: bool = False`; `compute_phases` emits
`provisional = spec.needs_cycles and not ctx.segmentation_reliable`. The UI renders a provisional metric
with valence coloring SUPPRESSED to neutral (never green/red) and says why in the hover overlay. This
reuses the existing neutral path rather than inventing a new visual, and keeps the "no false confidence"
doctrine intact. `SCHEMA_VERSION` 2 → 3 (additive field).

**D9 — `dead_spot_timing` = mean seconds from cycle start to that cycle's velocity minimum**, averaged
over cycles whose `start_idx` falls inside the swim window. Matches the registry unit `s`.

**D10 — Registry strips render ABOVE `CycleCharts`** in the Swimming section. The strips are the
phase-model content; the per-cycle charts are supporting detail beneath them.

**D11 — `breathing_dip` is DELETED from `REGISTRY`**, replaced by a comment recording why (a 1-D axial
encoder cannot observe which strokes were breaths). Keeping a permanently-unfillable row would make the
UI render a metric that can never have a value.
</planning_decisions>

    - REPLACE `splits`, `phase_time_budget`, `phase_dist_budget`, `vel_envelope` with the per-element

      `sr_dps_coupling` and `dead_spot_timing` also get `needs_cycles=True`.

    **Compute functions** — reuse the existing `_bounds` / `_idx` / `_window` / `_span_distance`
    helpers. Add a `_swim_window(ctx)` mirroring `_uw_window`. Every fn returns a raw float or None;
    never raise, never return NaN.
    - `ivv` — std/mean of `vel` over the swim window. Structurally identical to `_compute_uw_ivv`,
      but WITHOUT its breaststroke gate (that gate exists for kick metrics, not window variance).
    - `breakout_vel` — mean `vel` over a short window starting at `stroke_start_s`. A single sample is
      noise; pick a fixed span (~0.5 s) and name it as a module constant.
    - `breakout_vel_loss` — underwater mean speed minus the first post-breakout trough velocity.
    - `breakout_vs_steady` — breakout-window mean / trimmed mid-swim mean. TRIM the last portion of the
      swim window before taking the steady mean: `finish_s` is the weakest boundary in the model
      (MAE 2.76 s) and an untrimmed tail drags the denominator. Name the trim fraction as a constant.
    - `splits_{5,10,15,20,25}m` — build with a small factory over the distance list. Anchor 0 m at
      `dist[dive_start_idx]`; each split is the MEAN VELOCITY over its own 5 m segment (registry unit
      is m/s, not elapsed time). Return None when the swim never reaches that distance.
    - `accel_asymmetry` — fraction of swim-window samples with positive accel vs negative.
      Return None when `ctx.accel` is empty (pre-Phase-64 sessions).
    - `sr_dps_coupling` — over cycles whose `start_idx` lies in the swim window, correlate per-cycle
      stroke rate (`60 / duration_s`) against per-cycle DPS (`dist_m`). Return None with fewer than
      3 usable cycles or zero variance in either series.
    - `dead_spot_timing` — D9. Per qualifying cycle, `(argmin(vel[start_idx:end_idx]) ) / fs`; return
      the mean. None with no qualifying cycles.
    - `phase_time_budget_*` — each phase's duration / total (`dive_start_s`→`finish_s`). None when the
      total is unresolvable.
    - `phase_dist_budget_*` — same three windows over Δ`dist` / total Δ`dist`.
    - `vel_envelope_*` — max `vel` within Start / Underwater / Swim, plus `_overall` over
      `dive_start_s`→`finish_s` (D6).
    - `jerk_smoothness` — mean |Δaccel|/Δt over the swim window; None when `ctx.accel` is empty.

    Avoid: re-segmenting inside a compute fn (cycles arrive on the context, never recomputed);
    clamping a boundary that falls outside the trace (`_idx` returns None deliberately — AC-1 wants
    None, not a truncated number).

    **Tests** — extend `tests/test_phase_metrics.py`: a synthetic-trace case per metric group,

    `provisional` flag both ways, and a registry-integrity check that every spec still satisfies the
    `status`/`compute` invariant and that no removed key lingers.
