<objective>
## Goal

Give the underwater phase a **trustworthy start boundary** and turn the resulting window into the
four window-arithmetic underwater metrics, then roll the new boundary out to every surface that
reads a phase decomposition.

Concretely:
1. `metrics.detect_underwater_start` — the coach's own rule ("the underwater phase begins at the
   first big velocity dip"), measured this session at **mean |error| 0.13 s / 35 of 38 within
   0.5 s / 0 missed** against the 38 hand-marked annotations, versus the incumbent dive-peak
   derivation's **1.23 s on only 10 of 38**.
2. Boundary resolution inside `phase_metrics` with the user's precedence: **coach annotation first,
   auto fallback second**, recorded per-key so a reader can tell which it got.
3. Four registry metrics flipped `planned → implemented`: `uw_duration`, `uw_distance`,
   `uw_avg_speed`, `uw_surface_ratio` — plus `pulldown_peak_vel` / `pulldown_duration` passed
   through for breaststroke, whose underwater content is a pulldown, not kicks (D3).
4. The improved boundary reaches the annotate page (`build_seed`) and every stored session
   (`tools/backfill_phases.py`), so annotating a session drops from four marks to one.

## Purpose

Phase 75-01 built the registry and the recompute seam but implemented zero metrics, by design
(D12). This is the first Step-2 increment. It is the *enabling* one: every other underwater metric —
kick count, distance per kick, tempo, consistency, per-kick decay, first-kick impulse, underwater
IVV — needs the same window, so the window has to be right before any of them are worth computing.

The measurement that motivated it is in this plan's `<context>` and is reproducible via the tool
Task 1 commits.

## Output

- A validated underwater-start detector + a committed scoring harness that reproduces its accuracy.
- `metrics_json.phases.boundaries` — the resolved four-boundary decomposition with per-key sources.
- Four underwater metrics live end-to-end (`/process`, `POST /recompute`, and backfilled onto the
  existing library).
- A better annotate-page seed for every session.
</objective>

## Measurement backing this plan (run 2026-08-19 against the live DB, read-only)

108 sessions, 38 annotations.

**Underwater start — the coach's first-big-dip rule, scored against the 38 hand-marked
`underwater_start_s` values.** Rule as implemented: from `dive_start`, take the surge peak
(max |v| within 4 s), then the FIRST velocity trough after it whose prominence ≥ `frac × v95`.

| prominence frac | median err | mean abs err | within 0.5 s | within 1.0 s | missed |
|---|---|---|---|---|---|
| 0.25 | 0.00 s | 0.43 s | 29/38 | 29/38 | 0 |
| 0.30 | +0.01 s | 0.24 s | 33/38 | 33/38 | 0 |
| 0.35 | +0.01 s | 0.18 s | 35/38 | 36/38 | 0 |
| **0.40** | **+0.01 s** | **0.13 s** | **35/38** | **37/38** | **0** |
| 0.50 | +0.02 s | 0.24 s | 33/38 | 35/38 | 1 |
| 0.60 | +0.07 s | 0.74 s | 24/38 | 30/38 | 1 |

Per stroke at 0.35–0.40: freestyle n=16 mean 0.15 s · butterfly n=17 mean 0.10 s · breaststroke
n=4 mean 0.03 s. The 0.30–0.40 plateau is broad and flat — this is not a knife-edge fit.
**Incumbent for comparison:** `underwater_start_s = baseline_end_s + dive_duration_s` (the dive
peak) is null on 84 of 108 sessions and, where it fires, mean |err| 1.23 s with only 3 of 10 within
1 s. It is systematically ~1.5 s early — it marks the top of the dive, not the end of the glide.

⚠ **Honest caveat, to be repeated in the SUMMARY:** the coach placed those 38 marks while looking
at the velocity trace on the annotate page, so "first big dip" may partly describe how the mark is
clicked rather than independent physiology. It is nonetheless the annotation contract's own
definition of the boundary, so it is the correct target for an auto seed.

**Underwater end — NOT solved, and deliberately out of scope (user directive, 2026-08-19):**
*"Defer the end boundary to later for stroke plan. For now, assume whatever the input for end
boundary is correct."* For the record, so a later plan does not repeat the work: the current auto
`stroke_start` is ~3–4 s off the coach's mark in both directions, and a rhythm step-down detector
tested this session (first inter-peak interval > 1.5× the running base) was **worse** — 17 of 37
no-detect, mean |err| 2.95 s where it fired. This is the same open problem as ROADMAP TODO #69 and
Phase 58's removed breakout marker.

  <files>metrics.py, tests/test_metrics.py, tools/score_underwater.py</files>
  <action>
    Add `detect_underwater_start(t, vel, baseline_end_idx)` to `metrics.py`, placed immediately
    after `detect_initial_phase` (its sibling in role). Signature and return convention match the
    module's other detectors: full-trace index, or `None` when it cannot answer.

    Algorithm — the coach's rule, at the prominence the measurement selected:
      - `_UW_SURGE_WINDOW_S = 4.0`, `_UW_START_PROM_FRAC = 0.40` as module constants next to the
        other `_WINDOW_*` / `_PEAK_*` constants, each with a one-line comment naming the measured
        table in this plan's context.
      - Slice `seg = vel[baseline_end_idx:]`; return None if it is shorter than one second of samples.
      - `v95 = np.nanpercentile(np.abs(seg), 95)`; return None if not finite or <= 0.
      - Surge peak: `pk = nanargmax` over the first `_UW_SURGE_WINDOW_S` of `seg` (whole slice if shorter).
      - `find_peaks(-seg[pk:], prominence=_UW_START_PROM_FRAC * v95)`; the FIRST result is the dip.
      - Return `baseline_end_idx + pk + first_trough`, or None when no trough qualifies.

    ⚠ Use `np.nanpercentile` / `np.nanargmax`, NOT the module's `_window_v95` helper. `_window_v95`
    calls `np.percentile`, which returns NaN if any sample is NaN — and this detector is also
    reached from the recompute path, whose input is a STORED `velocity_profile` that can contain
    nulls. Put that reason in the docstring so nobody "consolidates" it later.

    Do NOT call the new detector from `compute_session_metrics`, `detect_swim_window`, or the
    segmenter. It is consumed only by `phase_metrics` (Task 2) — that is what keeps AC-6 true.

    Tests in `tests/test_metrics.py` (new class `TestDetectUnderwaterStart`), synthetic signals only:
      - a surge-then-dip-then-oscillation trace returns the dip index within one sample;
      - a monotonically rising trace with no qualifying dip returns None;
      - a trace containing NaNs still returns the dip (the nan-tolerance contract above);
      - a trace shorter than one second returns None;
      - a dip whose prominence sits below the threshold is not selected, but the next larger one is.

    `tools/score_underwater.py` — read-only, service-role, modeled directly on
    `tools/underwater_probe.py` (copy its `.env` loading, its `sys.path` shadowing workaround, and
    its no-write / no-PII discipline; print session id prefix + stroke only). It must:

      - print the per-prominence sweep table (0.25 / 0.30 / 0.35 / 0.40 / 0.50 / 0.60) plus a
        per-stroke breakdown and every session with |error| > 0.5 s;
      - accept `--prom` to score a single value.
