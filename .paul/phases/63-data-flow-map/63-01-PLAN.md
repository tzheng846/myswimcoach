  <action>
    Create a committed dev tool that regenerates every live figure the document cites, so the
    snapshot is reproducible instead of a one-off. Model it on the existing
    `tools/introspect_schema.py` — same `.env` loading via python-dotenv, same
    `sys.path` guard (the local `supabase/` folder shadows the installed `supabase-py`
    package; strip bare '' and '.' entries before importing).

    It must report:
    - row count per table for all 7 tables
    - for `sessions`: non-null count per column, over all rows
    - stroke_type and upload_status distributions
    - the KEY STRUCTURE of each jsonb column, sampled from real rows: for metrics_json the
      nested key sets under session / cycles[0] / data_quality / initial_phase; for
      session_annotations the phases keys and the stroke_marks_s element shape; for
      reports.config_json its keys; for velocity_profile / distance_profile the element type
      and array length alongside that row's sample_rate_hz
    - the count of sessions with video_path set but video_origin_s NULL

    ⚠ READ-ONLY IS A HARD REQUIREMENT. Use only `.select()`. The module must contain no
    `.insert(`, `.update(`, `.upsert(`, `.delete(`, or `storage...remove/upload` call. This
    tool runs against the production database with the service-role key, which bypasses RLS.

    ⚠ NO PII IN OUTPUT. Report keys, types, counts and lengths — never field values. Do not
    print `athletes.name`, `parent_email`, `parent_name`, `dob`, `coaches.email`, or session
    `name`/`notes` contents. Counting how many are non-null is fine; printing them is not.

    Avoid: writing a snapshot JSON artifact to the repo — the numbers live in DATA-FLOW.md and
    a second copy would drift. Print to stdout only.
  </action>
