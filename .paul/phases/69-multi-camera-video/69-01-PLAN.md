<objective>
## Goal
Add the storage + API foundation for up to 3 EXTERNAL videos per session, alongside the existing
phone/primary video — **additively**, so nothing that reads the legacy `sessions.video_path` /
`video_origin_s` columns (5 web sites + mobile) changes, and no data is migrated.

## Purpose
Phase 69's multi-cam player and Videos page (69-02/03) need somewhere to store and serve up to 4
angles. The safe foundation (CONTEXT D1, refined) is: phone/primary stays in the legacy columns
untouched; a new `session_videos` table holds the ≤3 externals; a small set of new endpoints does
external CRUD + returns a unified list (primary + externals) with signed URLs for the player.

## Output
- `supabase/patch_12_session_videos.sql` — the `session_videos` table (RLS on, API-only).
- `api.py` — `GET/POST/PATCH/DELETE /sessions/{id}/videos[/{video_id}]`; legacy `/video` +
  `/video-url` UNCHANGED.
- `tests/test_api.py` — external CRUD, cap, size guard, ownership; legacy endpoints unaffected.
</objective>

        id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),

        storage_path text NOT NULL,
        origin_s     double precision,
        label        text,
        created_at   timestamptz NOT NULL DEFAULT now()

      CREATE INDEX IF NOT EXISTS session_videos_session_id_idx ON session_videos(session_id);
      ALTER TABLE session_videos ENABLE ROW LEVEL SECURITY;

    deleting a session drops its externals. User-applied in the SQL editor, like patch_09..11.
