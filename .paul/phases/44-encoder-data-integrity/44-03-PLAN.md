<objective>
## Goal
Fix the two defects that survived the 44-02 checkpoint: (1) the startup pulse — the 44-02
warmup gate broke early on the stable garbage plateau (`settled angle≈3444`), so the
transient still entered the buffer; and (2) the video↔device overlay desync — the in-app
overlay is ~2 s off because it trusts a video start-timestamp taken before the camera's
first frame.

## Purpose
44-02 fixed the BLE packet loss (indications ✅) but left these two. Both block usable
recordings: the pulse corrupts the start of every velocity trace; the desync makes the
video-overlay feature (the "why not TritonWear" proof point) misleading.

## Output
- Firmware: a warmup that can't be fooled by a stable-but-wrong plateau.
- iOS: an overlay that aligns video and device data correctly without manual nudging.
</objective>

<task type="auto">
  <name>Task 1: Warmup minimum-time floor (stop breaking on stable garbage)</name>
  <files>ESP_32_V5/ESP_32_V5.ino</files>
  <action>
    The stability gate alone is fooled because the transient is a STABLE plateau (12 identical
    3444s pass "5 within ±4"). Add a minimum-time floor so the warmup cannot break until the
    plateau is provably past:
    - Add WARMUP_MIN_MS (suggest 150 — comfortably above the observed ~55 ms transient) near
      the other WARMUP_* defines; raise WARMUP_MAX_MS to ~300.
    - In the warmup loop, gate the stability break on elapsed time:
      `if (stable >= WARMUP_STABLE_N && (millis() - warmStart) >= WARMUP_MIN_MS) break;`
      so it always discards ≥ WARMUP_MIN_MS, then breaks once stable, capped at WARMUP_MAX_MS.
    - Keep seeding lastGoodAngle from the final (settled) read.
    Note the Phase-41 race-start cost: warmup discards ≤ WARMUP_MAX_MS after the blare; the
    floor (~150 ms) mostly overlaps reaction time. If a later trace shows the plateau lasting
    longer than the floor, raise WARMUP_MIN_MS.
    Root-cause note (not this plan): the 3444 plateau itself (AS5600 raw-angle settling at
    record start) could be investigated via the CONF register / power mode to remove the
    transient entirely and drop the discard — deferred.
    Avoid: relying on stability alone (the defect); an unbounded wait.
  </action>
  <verify>Warmup log reports settled angle ≈ true (~651); TRACE_BUFFER trace head starts at
    the true angle; app velocity has no startup pulse.</verify>
  <done>AC-1 satisfied.</done>
</task>

<task type="auto">
  <name>Task 2: End-anchor the video overlay sync</name>
  <files>../swimnetics-mobile/src/screens/VideoOverlayScreen.js</files>
  <action>
    Replace the start-timestamp anchor (wrong by the camera warm-up) with an end-anchor that
    uses the shared stop: one Stop tap ends both the camera and the device, so their END phone
    times are ~equal. Therefore the video's first frame sits at (deviceDuration − videoDuration)
    in the device timeline:
    - deviceDurationS = time[time.length-1] − time[0] (already a prop).
    - videoDurationS = player.duration (expo-video; available after the video loads — read it
      once loaded, e.g. poll in the existing ~20 Hz interval or on a status/ready change; until
      known, leave the marker inert rather than guessing).
    - videoOriginS = deviceDurationS − videoDurationS. Keep `tetherT = currentTime +
      videoOriginS + manualOffsetS` and the ±nudge for residual stop-latency.
    - Keep sessionStartPhoneMs/videoStartPhoneMs only for the debug line (no longer the anchor);
      update the gating so a missing videoStartPhoneMs doesn't blank the screen if durations are
      available. This is warm-up-agnostic — it self-corrects whatever the camera delay is.
    Document the one assumption (camera and device stop on the same tap; if the video hits
    maxDuration or the buffer fills, ends differ → nudge covers it).
    Avoid: touching RecordScreen's capture timing or adding native first-frame callbacks.
  </action>
  <verify>npx expo export --platform ios exits 0; on device, origin ≈ deviceDuration −
    videoDuration (~2 s) and a real event aligns at manualOffset 0.</verify>
  <done>AC-2 satisfied.</done>
