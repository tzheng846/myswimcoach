<objective>
## Goal
Make a web-uploaded video first-class on the **report card**: playable inline (one angle + velocity
overlay) and added via a **modal** — no page navigation. Fixes the UAT bug where an external clip
uploaded on the web "vanished" (showed only a "Videos (1)" link, never inline).

## Purpose
Phase 69's additive data model split video into two stores — the phone/primary in the legacy
`sessions.video_path` column, web uploads in the `session_videos` table. The report-card inline
player reads only `video_path`, so **every web upload is invisible inline** (the report card is
effectively phone-only). Reading the unified `GET /videos` list instead makes the user's already-
uploaded external reappear with no migration, and delivers the "add via popup, watch on the report
card" flow they asked for.

## Output
- Report-card inline video sourced from the unified `GET /sessions/{id}/videos` list (phone if present,
  else first uploaded angle), watch-only, with the existing trace overlay.
- A new `AddVideoModal` (file-picker popup) wired to an "Add video" button on the report card.
- `VideoPane`/`VideoTracePanel` generalized to play a camera identified by a **direct signed URL**
  (the unified-list shape), not only the legacy `video_path`.
- `.paul/phases/71-video-surface-rework/71-01-SUMMARY.md`.
</objective>
