<objective>
## Goal
Add a public "Build log" blog to the marketing site (`web/`): a `/blog` index that
lists posts and individual `/blog/[slug]` post pages, linked from the top Nav and the
Footer. Seed it with the founder's dev-journal turned into **5 thematic posts** that
cover where Swimnetics is now, the struggles behind it, and what's coming — written in a
**lightly polished candid** voice and styled to match the existing light-themed static
pages (`/faq`, `/privacy`).

## Purpose
The site today only sells; it has no "here's the real story / here's where this is going"
surface. A founder build log gives prospects and referrals (the data-scientist contact,
ASP coaches) something honest and human to read, reinforces the "we tell you plainly what
works and what doesn't" positioning already in the FAQ, and is a place future product
updates can land.

## Output
- NEW `web/lib/blog.js` — the post corpus (5 posts: slug, title, kicker, excerpt, ordered body blocks).
- NEW `web/app/blog/page.js` — blog index (post cards → post pages).
- NEW `web/app/blog/[slug]/page.js` — dynamic post page (static-generated, 404 on unknown slug).
- EDIT `web/components/Nav.js` + `web/components/Footer.js` — add a "Blog" link.
- SUMMARY at `.paul/phases/46-marketing-blog/46-01-SUMMARY.md`.
</objective>

    2. slug "laughed-off-the-deck" — kicker "Field testing" — the ASP demo arc: switching the

       rabbit hole: wanting an elegant mechanical-only solution → researching tape-measure /
       retractable-dog-leash mechanisms → spiral spring, then learning it isn't constant-force
       (and constant-force springs are pricey / need a gear ratio) → giving up on mechanical
       and committing to a motor → power-management headache (one supply for both the ESP32 and
       the motor without frying anything) → motor driver + USB-C breakout + DuPont wiring that
       wouldn't spin → soldering, then the protoboard + schematic epiphany, and the motor
       finally spinning → the back-EMF scare (the swimmer back-driving a 3000 rpm / 1:250
       geartrain) → the one-way bearing that free-spins one direction and locks to transmit
       torque the other → dialing in print tolerances by trial and error, and the
       filament-saving trick of printing the body upside-down with a separate heat-pressed
       string guide.
    4. slug "teaching-the-software-to-see-a-stroke" — kicker "Signal processing" — the
       segmentation breakthrough: breaststroke segments easily but other strokes don't →
       FFT / spectral analysis failing → weighing ML but not wanting to hand-label → a mentor
       suggesting the matrix profile (elegant, just repeated Euclidean distance) → it not
       generalizing (motifs lock onto a few cycles) → trying wavelet analysis, which works,
       generalizes across strokes, and — unexpectedly — separates the kick and the pull as
       distinct frequency bands. (Keep this honest: stroke segmentation for non-breaststroke
       is still early/experimental — matches PROJECT.md `segmentation_reliable=False`.)
    5. slug "where-swimnetics-is-now" — kicker "Where we are & what's next" — current state +
       roadmap: the software/business backbone today (the iOS app, Supabase storage, the
       Railway API, the website now live at swimnetics.com); a former-swimmer-turned-data-
