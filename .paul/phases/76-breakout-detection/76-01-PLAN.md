<objective>
## Goal
Ship a **kick-band-disappearance breakout detector** for **freestyle** (and backstroke, flagged
unvalidated) that places `stroke_start_s` / `ip_end` at the true Underwater→Swim transition. Gate it
per-stroke and behind a confidence check that **refuses** (falls back to today's detector) when the
signal is weak — so it never ships a confident wrong answer. **Butterfly and breaststroke are
untouched.**

## Purpose
The breakout is the single biggest limiter on the race-phase model: it blanks 48 of 108 sessions'
underwater metrics and it gates the kick window that 75-03 depends on. **Six signal levers were
measured and failed** (amplitude, mean-vel step, accel surge, 2× harmonic, rhythm step-down,
first-deep-trough). The user proposed a seventh — *"dolphin kick is mostly cyclic, so a frequency
band is active for an extended period; breakout = when that band disappears"* — and it is the first
one that works. Because the kick band (~1.8–3.2 Hz) sits **above** production's 0.25–2.0 Hz ridge
window, every prior ridge-based detector was structurally blind to exactly the signal that carries
the breakout.

## Validation already done (tools/breakout_band_probe.py, live DB, 33 annotated free/fly sessions)
Scored against the coach's `stroke_start_s` marks:

| stroke | current median \|err\| | **kick-band** | within 0.5 s |
|---|---|---|---|
| **freestyle** (n=16) | 2.07 s | **0.30 s** | **11/16** (current 2/16) |
| butterfly (n=17) | 2.43 s | 4.46 s (WORSE) | 3/17 |

Freestyle is a decisive win; **butterfly fails for a principled physical reason** — fly keeps
undulating at ~2 Hz on the surface (2 kicks per arm cycle), so the kick band never disappears
(`Pk_uw/sf ≈ 1`, confirmed on the scalogram). The three freestyle misses are weak/short-underwater
sessions where the swimmer kicks past the breakout — the confidence gate must refuse these.

## Output
- `metrics.detect_breakout_kickband(...)` — the new detector + its constants (additive).
- A per-stroke override in `compute_session_metrics` (free/back only) that sets `ip_end` from it
  when confident, superseding the `detect_swim_window` value; propagates to `initial_phase` →
  `build_seed.stroke_start_s` → the underwater window with **no change to annotations.py /
  phase_metrics.py**.
- `tools/breakout_band_probe.py` hardened into the committed accuracy scorer.
- New tests; suite stays green; butterfly/breaststroke byte-identical.
</objective>

<decisions>
Resolved at plan time (2026-08-20), from the validation run:

- **D1 — per-stroke: freestyle + backstroke ONLY.** Butterfly & breaststroke are NOT eligible; the
  detector is never called for them and their `ip_end` is byte-identical. Backstroke has **zero**
  ground truth (n=0) but is physically analogous to freestyle (surface = arm strokes + flutter, not
  undulation); it ships flagged **unvalidated**, mirroring 59-05's backstroke stance.
- **D2 — refuse, don't guess.** When no sustained kick-band run exists after `underwater_start`
  (weak/short underwater — the 3 freestyle misses) or the band doesn't cleanly drop, return **None**
  and the current `detect_swim_window` `ip_end` stands. False-positive cost = only the improvement;
  false-negative cost = a confident wrong window. Same asymmetry as `_WINDOW_MIN_CYCLES`.
- **D3 — the band is fixed + physical (1.8–3.2 Hz), not fit per session.** Constants are
  physically motivated (dolphin-kick rate), not tuned to the 33-session corpus, honoring 59's
  no-overfit rule. Task 3 reports a robustness sweep (band/frac ±) but does not fit constants to
  individual sessions.
- **D4 — integrate at `ip_end`, not just the seed.** Overriding `ip_end` in
  `compute_session_metrics` fixes BOTH the underwater window (via `initial_phase` →
  `build_seed.stroke_start_s`) AND segmentation start (the breakout cycle is no longer lost to the
  ~2 s settle lag). One seam, both wins.
- **D5 — existing sessions need a backfill (separate, post-approval).** Newly-processed/recomputed
  sessions get the fix immediately; the ~37 stored free/back sessions re-scale on reprocessing —
  the standing comparability-break + backfill pattern (57 / 59-03 / 61-01 / 65). Not a task here.
- **D6 — new Phase 76, and 75-03 (kick metrics) now depends on it.** The kick window is
  `[underwater_start, stroke_start]`; a correct `stroke_start` must land before the kick detector
  is trustworthy. Flag at 75-03 apply time.
</decisions>

      _KICK_BAND_HZ        = (1.8, 3.2)   # dolphin-kick band — ABOVE production's 0.25-2.0 Hz ridge
      _KICK_SCALO_HZ       = (0.5, 5.0)   # wider scalogram so the kick band is visible; 96 scales
      _KICK_DROP_FRAC      = 0.35         # band goes "quiet" below this × the run-peak power
      _KICK_HOLD_S         = 0.6          # quiet must persist this long → breakout
      _KICK_MIN_RUN_S      = 1.0          # a sustained kick run shorter than this → refuse (D2)

      def detect_breakout_kickband(t, vel, uw_start_idx, swim_end_idx=None):
          """Underwater→Swim breakout via kick-band disappearance (free/back). Full-trace index,
          or None when the band carries no trustworthy answer (refuse convention)."""

    - Build a wider CWT over _KICK_SCALO_HZ with the SAME wavelet (_WAVELET) + _detrend_for_cwt +
      np.nan_to_num as production (stored profiles can carry nulls). Do NOT reuse _cwt_ridge (its
      0.25-2.0 Hz grid cannot see the kick band — that is the whole point).
    - kick-band power = mean |CWT|² over freq bins in _KICK_BAND_HZ, smoothed ~0.4 s.
    - From uw_start: find the sustained active run (power > _KICK_DROP_FRAC × 95th-pct). REFUSE
      (None) if the active run is shorter than _KICK_MIN_RUN_S (the weak/short-underwater misses).
      Breakout = first sample after the run where power stays below the drop line for _KICK_HOLD_S.
      Clamp inside (uw_start, swim_end) when swim_end_idx given.
    - Guard: return None on degenerate uw_start, <2 s of signal, flat/all-NaN band, or no drop.
    - Avoid: a global timing offset (59-04: error is scatter, not lag); any amplitude/mean-vel test
      (65-01 refuted); calling it for butterfly (fly retains the band — measured).

    Tests (a new TestBreakoutKickband class): a synthetic segment = 2 Hz burst (kicks) then 1 Hz
    (strokes) → breakout at the transition; a no-kick segment (pure 1 Hz) → None; a too-short kick
    run → None; an all-NaN / degenerate window → None (no raise); result strictly inside the window.
