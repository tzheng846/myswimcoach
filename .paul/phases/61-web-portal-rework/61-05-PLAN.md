  <name>Task 1: Fetch video columns and wire both VideoPanes</name>
  <files>web/app/app/compare/page.js</files>
  <action>
    Extend both detail queries with `video_path, video_origin_s`.

    Render one `VideoPane` per session, passing:
      - `video={video_path ? {path, origin_s: video_origin_s ?? null} : null}`
      - `sessionDurationS` derived from that session's own profile length ÷ its own
        `sample_rate_hz` (NULL → 100), matching `sessions/[id]/video/page.js`
    ⚠ `origin_s` must pass through as **null**, not 0. 61-03 found this exact `?? 0` defect at two
    separate sites; a third would silently un-sync every phone-uploaded video on this page.
    ⚠ `sessionDurationS` is REQUIRED for the end-anchor to compute. Omitting it is a silent
    no-op — the pane falls back to whatever is stored, which for these sessions is nothing.

    Hold each pane's video in its own state so `onVideoChange` (upload / origin save) updates only
    that side. **Do NOT share one state object between the two panes.**

    ⚠ Both panes may auto-save an origin on first load. That is safe and intended — different
    session ids, different endpoints, each guarded on its own `savedOrigin == null` — but say so
    in the SUMMARY rather than leaving a reader to wonder whether two writes race.
    ⚠ Do NOT pass `seekRef`/`frameStepRef` unless something drives them; unused refs imply a
    wiring that does not exist.
  </action>
  <verify>npm run build clean; a NULL-origin session shows "computed (end-anchored)" in the pane's provenance line; uploading on one side leaves the other unchanged</verify>
