<objective>
## Goal
Extend metrics.py to detect dive-off-block and underwater pulldown phases, add a time-to-distance metric, and update the FastAPI backend to store full session data (raw CSV + 100Hz velocity + distance profiles) in Supabase.

## Purpose
Demo requires robust detection for a real pool scenario: swimmer dives off the block, does an underwater pulldown, then cycles breaststroke. Currently the algorithm assumes wall push-off only — the initial high-velocity surge from a dive would be misdetected as a stroke. Session history (Phase 8) needs full profiles stored server-side.

## Output
- `metrics.py`: `detect_initial_phase()`, `time_to_distance()`, updated `compute_session_metrics()`
- `api.py`: `/process` stores raw CSV to Supabase Storage, stores full session row (metrics + profiles), returns `distance` array
- `supabase/patch_02_profiles_headwaist.sql`: adds `velocity_profile`, `distance_profile` to sessions; adds `head_waist_m` to athletes
</objective>

  <action>
Add two new public functions and update compute_session_metrics():

**`detect_initial_phase(t, vel, baseline_end_idx)`**
Goal: identify the dive surge and underwater pulldown before cyclic breaststroke begins.

Logic:
1. Compute v95 = np.percentile(abs(vel[baseline_end_idx:]), 95)
2. Search for the first deep trough AFTER baseline_end_idx using find_peaks(-vel, height=-0.20*v95, distance=max(1, int(0.5*fs))). The first such trough = `initial_phase_end_idx`. If none found within 15 seconds of baseline_end, set initial_phase_end_idx = baseline_end_idx (no initial phase).
3. In the window [baseline_end_idx, initial_phase_end_idx], find prominent peaks: find_peaks(vel, prominence=0.15*v95).
   - 0 peaks → dive_detected=False, pulldown_detected=False
   - 1 peak → dive_detected=False, pulldown peak = that peak
   - 2+ peaks → dive peak = first, pulldown peak = last (highest among remainder)
4. Compute durations:
   - dive_duration_s: if dive_detected, time from baseline_end_idx to first trough between dive and pulldown peaks (or to pulldown peak start if no intermediate trough)
   - pulldown_duration_s: time from pulldown peak start to initial_phase_end_idx

Returns dict:
```python
{
    "initial_phase_end_idx": int,
    "dive_detected": bool,
    "dive_duration_s": float | None,
    "pulldown_detected": bool,
    "pulldown_peak_vel_ms": float | None,
    "pulldown_duration_s": float | None,
}
```

Fallback: if any exception, return {"initial_phase_end_idx": baseline_end_idx, "dive_detected": False, "pulldown_detected": False, "dive_duration_s": None, "pulldown_peak_vel_ms": None, "pulldown_duration_s": None}

**`time_to_distance(t, dist, target_m, baseline_end_idx, head_waist_m=0.0)`**
- dist_from_start = dist - dist[baseline_end_idx] (zeroed at swim start)
- waist_target = target_m - head_waist_m (wheel reads waist position; head is head_waist_m ahead)
- If waist_target <= 0 or waist_target > dist_from_start[-1]: return None
- Use np.searchsorted(dist_from_start[baseline_end_idx:], waist_target) to find crossing index
- Return float(t[baseline_end_idx + idx] - t[baseline_end_idx])

**Update `compute_session_metrics(t, vel, dist, head_waist_m=0.0)`**:
- After detect_phases(), call detect_initial_phase(t, vel, b_end)
- Pass initial_phase["initial_phase_end_idx"] as the start of segment_cycles_trough() instead of b_end
  (so t_swim = t[initial_phase_end:swim_end], vel_swim = vel[initial_phase_end:swim_end])
- When offsetting cycle indices back to full array, use initial_phase_end_idx not b_end
- Add to return value: result["initial_phase"] = initial_phase dict
- Do NOT change any existing session/cycle metric keys — additive only

Avoid: changing _BASELINE_THRESH or other tuning constants; touching extract_cycle_peaks or any metric formulas.
