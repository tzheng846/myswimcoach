<objective>

## Goal

Make `/app/sessions/[id]/video` enter a real fullscreen stage that shows the video **and** a live
velocity trace at the same time: a translucent, full-screen-width strip pinned to the bottom,
showing a 2 s window that follows the playhead at 60 Hz, with cycle boundaries, a live m/s
readout, click-to-seek, and the sync-offset repair controls.

## Purpose

The user cannot currently watch a swim and read its velocity together — the video is capped at
`clamp(140px,26vh,420px)` and the native fullscreen button promotes the `<video>` element alone
into the browser's top layer, leaving the chart (a DOM sibling) behind. This is the surface where
footage and encoder data are compared, so it is also the first place a wrong `video_origin_s` or a
mis-segmented cycle becomes *visible* rather than merely stored.

## Output

- `TraceOverlay.js` (new) — hand-rolled SVG trace, viewBox-panned by `requestAnimationFrame`.
- `FullscreenControls.js` (new) — custom control bar (the native one's fullscreen button is the trap).
- `VideoPane.js` — a `fullscreen` prop that swaps card chrome + native `controls` for the bare
  video + custom bar. **Windowed path unchanged.**
- `page.js` — the fullscreen stage (the element that goes fullscreen), `metrics_json` in the
  select, idle/auto-hide timer, keyboard handling.

</objective>

- `page.js:119-143` renders `<VideoPane>` and `<VelocityChart>` as **DOM siblings** — the cause.
- `VideoPane.js:239-247` sets `controls` on the `<video>`; `:247` is the `max-h` cap.
- Sync contract: `sessionTime = effectiveOriginS + video.currentTime` (`VideoPane.js:86-96`).

- `fsHz = row.sample_rate_hz > 0 ? row.sample_rate_hz : 100` (`page.js:69`). Never hardcode 100.
- The annotate page calls `<VideoPane>` at `page.js:426-436` with **no** `fullscreen` prop, so
  every new prop must default to the current behaviour.
- Theme tokens (`web/app/globals.css`): trace `--color-primary #2196f3`, playhead
  `--color-amber #f59e0b`, boundaries `--color-navy #1e3a5f`.

  <name>Task 1: TraceOverlay — SVG velocity strip with a viewBox-panned 2 s window</name>
  <files>web/components/portal/TraceOverlay.js</files>
  <action>
    New client component. Props:
    `velocity` (array), `fsHz`, `cycles` (array), `videoElRef` (ref to the &lt;video&gt;),
    `originS` (number|null), `onSeek` (fn(sessionTimeS)), `dimmed` (bool).

    Rendering model — this is the whole point of the component, do not deviate:
    - Build the polyline ONCE with useMemo, in DATA coordinates: x = sampleIndex / fsHz
      (seconds), y = velocity (m/s). Decimate to at most 4000 points. Skip null samples.
    - One &lt;svg&gt; with `preserveAspectRatio="none"` so the viewBox stretches to the box.
      Because that scales non-uniformly, EVERY stroked element needs
      `vector-effect="non-scaling-stroke"` or lines will render as wedges.
    - Y domain is FIXED over the whole trace (min/max + ~8% padding) so the trace does not
      jump vertically while panning. Y is flipped (higher velocity draws higher).
    - Cycle boundary &lt;line&gt;s are rendered by React once, in data coordinates. The viewBox
      clips them for free — do NOT filter them per frame.
    - The playhead is a &lt;line&gt; INSIDE the same svg, positioned in data coordinates. This is
      why it stays correct when the window is clamped at the trace ends and the playhead is
      therefore not centred.

    Animation — no React state in the loop:
    - One `requestAnimationFrame` loop reads `videoElRef.current.currentTime`, computes
      `sessionT = originS + currentTime`, then imperatively sets
      `svg.setAttribute("viewBox", ...)`, the playhead line's `x1`/`x2`, and the readout
      element's `textContent`.
    - Window: `WINDOW_S = 2`, `x0 = clamp(sessionT - WINDOW_S/2, 0, duration - WINDOW_S)`;
      if `duration < WINDOW_S`, show the whole trace.
    - ⚠ Do NOT drive the playhead from React state or from `timeupdate` — that is D7, and the
      whole reason this component exists instead of reusing VelocityChart (D6).
    - Cancel the frame on unmount. Bail out of a frame when `originS == null` or the video
      element is missing.

    Readout: velocity at `Math.round(sessionT * fsHz)`, clamped to the array, 2 dp + " m/s".

    Click-to-seek: onClick on the svg → map `clientX` through `getBoundingClientRect()` and the
    CURRENT window (`x0`, `WINDOW_S`) to a session time → `onSeek(t)`.

    Styling: absolutely positioned strip, full width, ~22vh tall (min ~120px), with a
    bottom-anchored dark scrim gradient behind it (a blue trace over sunlit water is otherwise
    unreadable — D3). Trace `#2196f3`, playhead `#f59e0b`, boundaries `#1e3a5f` dashed.
    `dimmed` fades the whole strip via opacity + a transition; keep it pointer-events-none
    while dimmed so a click to un-idle does not also seek.
  </action>
