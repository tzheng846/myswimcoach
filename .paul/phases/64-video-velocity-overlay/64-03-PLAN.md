<objective>

## Goal
Show the acceleration trace alongside velocity on both surfaces — the video overlay and the static
chart — as an independently-toggleable, separately-scaled stacked trace with its own colour.

## Purpose
Completes the user's ask (Phase 64-02/03): velocity and acceleration in view at the same time,
each toggleable. Reads `sessions.acceleration_profile` (populated by 64-02).

## Output
- `TraceOverlay`: a second stacked strip for acceleration (own scale, zero line, own colour, own
  readout) sharing the same rolling window / scrub / playhead.
- `AccelerationChart` (new): a static recharts chart with a signed y-axis + zero line, stacked
  under `VelocityChart` on both pages.
- Independent velocity/acceleration toggles + an acceleration colour picker, wired page-level so the
  overlay and the static chart stay in sync.

</objective>

## Decisions carried from the 64-02/03 discussion (2026-08-14)
- Data source: DB column `acceleration_profile` (64-02). Web reads it; NULL → no acceleration
  (pre-backfill / genuinely absent), toggle draws nothing rather than erroring.
- Both surfaces: overlay AND static chart.
- Layout: STACKED — separate strips/charts, each its own scale (acceleration is signed, so it needs
  a zero line and a symmetric-ish scale). NOT overlaid on one axis.
- Toggles: independent velocity + acceleration; default velocity ON, acceleration OFF; persisted.
- Acceleration gets its OWN colour picker (distinct default from velocity's red — e.g. a high-sat
  cyan `#22d3ee`).
- ⚠ Visibility + colours are owned at the PAGE level and passed to both the overlay
  (VideoTracePanel) and the static charts, so one toggle keeps both surfaces in sync within a page.
  This moves the existing velocity colour/window state's OWNERSHIP up from VideoTracePanel to the
  page for the acceleration/visibility prefs; the window-span stays overlay-local.
</context>
