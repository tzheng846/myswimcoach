<objective>

## Goal
Persist the pipeline's acceleration as `sessions.acceleration_profile` so every session — new and
existing — carries an exact acceleration trace the web can read, with no per-request computation.

## Purpose
User wants an acceleration trace alongside velocity (Phase 64-02/03). The pipeline already computes
acceleration (`run_pipeline` returns `accel`) but `api.py:172` discards it as `_accel`. Acceleration
is a **pure, deterministic function of the stored velocity** (`vel_acc_extraction.py:135-138`:
decimate `vel` to 5 Hz → `np.gradient` → interpolate back), so existing rows can be backfilled
exactly from `velocity_profile` — no raw-CSV reprocessing.

## Output
- `acceleration_from_velocity(vel, fs)` extracted as a pure function, called by `run_pipeline`.
- `sessions.acceleration_profile` jsonb column (patch_10), written by `/process`.
- `tools/backfill_acceleration.py` — one-time exact backfill of existing rows.
- Regression tests: pipeline accel byte-identical after the refactor; `/process` stores the column.

</objective>
