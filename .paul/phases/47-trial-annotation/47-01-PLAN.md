<objective>
## Goal
Establish the trial-annotation backend: a `session_annotations` table + video columns on
`sessions`, a pure `annotations.py` module (seed-from-segmenter + validation), and the
production API contract — GET/PUT/DELETE `/sessions/{id}/annotations`, POST
`/sessions/{id}/video`, GET `/sessions/{id}/video-url` — that the web GUI (47-02), iOS
auto-upload (47-03), and metric recompute (47-04) all build against.

## Purpose
User needs to review recorded trials and hand-mark swim phases (dive → underwater
kick/pulldown → breakout → stroke → finish) + individual stroke boundaries, against the
velocity trace and (when available) video. Annotations are (a) ground truth for wavelet
segmenter tuning (16-06) and (b) manual corrections that will later drive metric
recomputation. This is the "established API" — later exposed to any app user, so it is
built production-grade from day one (auth, ownership, RLS), not as a dev script.

## Output
- `supabase/patch_07_annotations.sql` — session_annotations table + RLS, sessions.video_path
  + sessions.video_origin_s, private `videos` storage bucket (user-applied)
- `annotations.py` — pure module: `build_seed(metrics_json)` + `validate_annotation(doc, duration_s)`
- `api.py` — 5 new endpoints (annotations CRUD + video upload + signed video URL)
- `tests/test_annotations.py` — pure-module + endpoint tests (supabase mocked, no network)
</objective>

<acceptance_criteria>

## AC-1: Annotation contract (the established API)
```gherkin
Given an authenticated coach who owns a session
When they GET /sessions/{id}/annotations
Then they receive {"annotation": <saved doc or null>, "seed": <auto-generated draft>, "video": {"path": ..., "origin_s": ...} or null}
And the seed is built from metrics_json (stroke marks from cycles, dive/underwater/stroke-start from baseline_end_s + initial_phase, finish from last cycle end), with null for anything undetected
```

## AC-2: Save + validation
```gherkin
Given a coach PUTs an annotation doc {"phases": {dive_start_s, underwater_start_s, breakout_start_s, stroke_start_s, finish_s}, "stroke_marks_s": [...]}
When all present times are within [0, session duration] and phase times are non-decreasing in canonical order and stroke marks are sorted
Then the doc upserts into session_annotations (one row per session) and returns the saved doc
And partial docs (any subset of phases, empty stroke marks) are accepted — 422 only on out-of-range/mis-ordered times
```

## AC-3: Ownership + auth
```gherkin
Given a session belonging to another coach's team, or no/invalid JWT
When any annotation or video endpoint is called
Then the response is 404 (other team, matching existing PATCH /sessions behavior) or 401 (no auth)
```

## AC-4: Video attach + retrieval (optional per session)
```gherkin
Given a coach POSTs a video file (multipart) with optional video_origin_s to /sessions/{id}/video
Then it is stored in the private `videos` bucket at {session_id}.mp4 and sessions.video_path + video_origin_s are set
And GET /sessions/{id}/video-url returns a time-limited signed URL
And GET /sessions/{id}/annotations on a session with NO video still returns 200 with video: null (velocity-only annotation works)
```

  <action>
    annotations.py — pure functions, no I/O (matches metrics.py/ratings.py convention):
    - PHASE_KEYS = ["dive_start_s","underwater_start_s","breakout_start_s","stroke_start_s","finish_s"]
      (canonical order; "underwater" displays as "pulldown" for breaststroke — client concern).
    - build_seed(metrics_json) -> dict: best-effort draft from stored metrics —
      dive_start_s = session.baseline_end_s; stroke_start_s = initial_phase end (derive from
      initial_phase durations/keys if present, else first cycle start); stroke_marks_s =
      [c.start_idx/100 for each cycle] (idx→s at 100 Hz, same convention as 39-05 overlay);
      finish_s = last cycle end_idx/100; underwater/breakout = null unless initial_phase
      pulldown data allows a defensible estimate. Missing/None metrics_json → all-null seed.
      Never raises.
    - validate_annotation(doc, duration_s) -> list[str] of errors: unknown phase keys;
      non-numeric/negative/beyond-duration times; present phases mis-ordered vs PHASE_KEYS
      order (skip nulls); stroke_marks_s unsorted or out of range. Empty list = valid.
      Light-touch — do NOT require stroke marks inside the stroke phase span.
    api.py — 5 endpoints, all reusing the existing auth dependency + session-ownership
    lookup used by PATCH /sessions/{id} (session→athlete→team vs coach; 404 on foreign):
    - GET /sessions/{id}/annotations → {"annotation": row-or-null, "seed": build_seed(metrics_json),
      "video": {"path","origin_s"} or null}. duration for clients = len(velocity_profile)/100.
    - PUT /sessions/{id}/annotations → validate (422 with errors list on failure), upsert
      by session_id via sb_admin, set updated_by + updated_at, return saved doc.
    - DELETE /sessions/{id}/annotations → remove the row (204).
    - POST /sessions/{id}/video → multipart UploadFile + optional video_origin_s form field;
      upsert to videos bucket at f"{session_id}.mp4" (upload with upsert option, same
      storage call pattern as raw-csvs at api.py:258); update sessions.video_path/
      video_origin_s. Also accept a bare PATCH-style video_origin_s update (origin without
      re-upload) — implement as: file optional; if absent, only update origin (422 if
      neither provided).
    - GET /sessions/{id}/video-url → 404 if no video_path, else sb_admin signed URL
      (create_signed_url, ~3600 s) → {"url": ..., "origin_s": ...}.
    Avoid: modifying metrics.py / vel_acc_extraction.py (recompute is 47-04); no
    streaming/range proxying of video through Railway (signed URL keeps bytes off the API).
