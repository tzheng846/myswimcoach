<objective>
## Goal
Fix the live bug that blocks adding an athlete to a team: `POST /athletes` 500s with
`'SyncQueryRequestBuilder' object has no attribute 'single'`. Remove the invalid `.single()`
call on the insert chain, and pin `supabase`/`postgrest` so an unpinned transitive upgrade
can't silently reintroduce this class of breakage on the next Railway deploy.

## Purpose
Coaches cannot create athletes at all right now — a hard blocker on the core "add swimmer,
record session" flow (PROJECT.md Must-Have: athlete profiles). Root cause CONFIRMED against
the installed postgrest 2.30.1: `.insert()` returns a `SyncQueryRequestBuilder`, whose
`.select()` returns another mutation builder that has **no `.single()`** method — so Python
raises `AttributeError` before any network call. The dependency is unpinned in
requirements.txt, so a Railway redeploy (likely the Phase-47 push 627419c) pulled a
postgrest where this chain is invalid.

## Output
- `api.py` — `POST /athletes` insert chain: drop `.single()`, return `resp.data[0]`
- `requirements.txt` — pin `supabase==2.30.1` + `postgrest==2.30.1`
- `tests/test_api.py` — regression guard for the `.single()`-on-a-mutation-builder bug class
</objective>

## Root cause (verified locally, postgrest 2.30.1)
- `SyncQueryRequestBuilder` (returned by `.insert()`): `hasattr(..., "single")` → **False**, `hasattr(..., "select")` → True
- `SyncSelectRequestBuilder` (returned by table `.select()`): `hasattr(..., "single")` → **True**
- Therefore `.insert(...).select(...).single()` raises AttributeError; `.select(...).eq(...).single()` (the SELECT path used across the file) is fine.

## Blast radius
Confirmed by grepping every insert/upsert/update/delete in api.py: `POST /athletes` (L1307) is
the ONLY mutation that chains `.single()`. All other mutations end cleanly at `.execute()`.
Mobile client sends the correct payload — NO mobile-repo change is needed for this fix.
</context>
