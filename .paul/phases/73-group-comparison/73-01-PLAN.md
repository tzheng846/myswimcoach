<objective>
## Goal
Add a "Groups" mode to Compare: pick two labeled groups of one athlete's same-stroke swims and, per
metric, see both group means, every swim as a dot, the delta, and an honest clear/overlapping cue.
Web-only, metrics-first, no p-values (CONTEXT D1–D11).

## Purpose
Turns Compare into an A/B experiment tool ("does breathing matter?" = 3 no-breath vs 3 with-breath) —
alerting whether two conditions differ and where, without a spaghetti of traces.

## Output
- `web/lib/groupStats.js` (pure stats), `GroupCompare.js` (the mode), a "Groups"/"Two swims" toggle on
  the Compare page, and `73-01-SUMMARY.md`.
</objective>

<task type="auto">
  <name>Task 1: web/lib/groupStats.js — pure group statistics</name>
  <files>web/lib/groupStats.js</files>
  <action>
    Pure module, NO React/Next imports (so it runs under plain node for verification).
    - `groupStats(values)` → `{ n, mean, sd, min, max }` over the non-null numbers (sample SD, n−1
      denominator; `sd = null` when n<2). Ignores null/undefined.
    - `bandsOverlap(a, b)` → boolean: do `[a.mean−a.sd, a.mean+a.sd]` and the same for `b` overlap?
      (Used only when both n≥2.)
    - `metricComparison(metric, valuesA, valuesB)` → `{ a: groupStats, b: groupStats, deltaAbs, deltaPct,
      betterSide, separation }` where:
        • `deltaAbs = b.mean − a.mean`, `deltaPct = a.mean ? deltaAbs/Math.abs(a.mean)*100 : null`.
        • `betterSide`: use `metric.direction` — "higher" → the group with the larger mean is "better";
          "lower" → smaller mean is better; "neutral" → null (no better/worse).
        • `separation`: `a.n<2 || b.n<2` → `"insufficient"`; else `bandsOverlap(a,b) ? "overlapping" :
          "clear"`.
    Avoid: any significance test / p-value (D4); importing anything non-pure.
  </action>
  <verify>node sanity check: `node -e` importing the file (CommonJS-compat or via a tiny inline reimpl is NOT allowed — instead test by requiring the built logic) — run `node --input-type=module -e "import('./web/lib/groupStats.js').then(m=>{const c=m.metricComparison({direction:'higher'},[1,2,3],[5,6,7]); console.log(c.separation==='clear', c.deltaAbs===4)})"` prints `true true`.</verify>
  <done>AC-2/AC-3 stats foundation correct (mean/sd/delta/separation), verified under node</done>
</task>

  <action>
    New client component. Layout (D8/D10, reuse Compare's supabase pattern):
    - **Controls:** one athlete `<select>` (shared — both groups are the same athlete, D5) + a stroke
      `<select>` limited to strokes that athlete has. Two text inputs for group labels (defaults
      "Group A" / "Group B"). Colors: reuse `COLOR_A`/`COLOR_B` from CompareChart.
    - **Session assignment (prevents dual-membership by construction):** fetch that athlete's sessions for
      the chosen stroke (`supabase.from("sessions").select("id, created_at, name, stroke_type,
      session:metrics_json->session").eq("athlete_id",…).eq("stroke_type",…).order created_at desc`). Render
      each as a row with two toggle buttons [A][B]; clicking sets that session's assignment (A / B / none) in
      a single `assignment` map `{sessionId: 'A'|'B'}`. A session is therefore in at most one group. Show a
      colored chip per assigned row.
    - **Comparison:** when both groups have ≥1 assigned session, for each metric in `REPORT_METRICS` gather
      `valuesA`/`valuesB` from each member's `session[metric.key]`, call `metricComparison`, and render a
      **GroupMetricRow** (define inline or as a small local component):
        • metric label; group A mean and group B mean via `formatValue`; the delta (`formatValue` of
          `deltaAbs` + `deltaPct` in parens), tinted by `betterSide`+direction (green if B better, red if B
          worse, neutral grey for "neutral"/no better side);
        • a compact **SVG strip plot**: one shared horizontal axis over [min,max] of all values (pad ~8%);
          group A swims as dots just above the axis, group B just below, each colored by group, with a short
          vertical tick at each group mean; hand-rolled inline SVG (match the portal's existing SVG-chart
          style, no chart lib);
        • the separation cue: `clear` → "Clear difference" (accent), `overlapping` → "Overlapping — likely
          noise" (muted), `insufficient` → "Add ≥2 swims per group" (muted). NEVER a p-value.
    - Empty states: prompt to pick an athlete/stroke, then to assign swims to both groups.
    - ⚠ Model groups as an array-ready shape even though 2 render now (D7) — keep the A/B specialization
      thin so a future ≤5 is a UI change, not a rewrite.
    Avoid: fetching velocity traces (metrics only, D2/D9); any backend call; a chart library; letting a
    session sit in both groups.
