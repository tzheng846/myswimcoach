<objective>
## Goal
For a set of REAL free/back/fly sessions (starting with "indigo ray"), measure exactly why the
auto pipeline places `ip_end` / `stroke_start_s` inside the underwater dolphin-kick phase — then
recommend ONE detector approach for the 65-02 fix. Pure diagnosis: no production code changes.

## Purpose
The fix's design is a genuine fork (CONTEXT open call #1): repair `detect_swim_window`'s frequency
logic, or add a new arm-pull-surge breakout detector that supersedes the `ip_end` source for these
strokes. That fork is unanswerable without data — which detector source misfires, per stroke, and
whether a discriminating signal even exists. Guessing it would violate the plan format. This plan
buys the certainty 65-02 needs, using the reported bug ("dive + dolphin kicks segmented as cycles"
across free/back/fly) as ground truth.

## Output
- `tools/underwater_probe.py` — a repeatable diagnostic (precedent: `tools/rampup_impact.py`,
  `tools/dataflow_probe.py`).
- `.paul/phases/65-underwater-phase-detection/65-01-FINDINGS.md` — per-session measurement table,
  per-stroke root cause, and a single recommended detector approach.
</objective>
