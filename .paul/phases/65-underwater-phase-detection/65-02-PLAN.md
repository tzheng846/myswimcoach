<objective>
## Goal
Repair `detect_swim_window` so a **low-railed CWT ridge no longer collapses `ip_end` to `b_end`**
(Mode C / "indigo ray" `6ececa0f`), which currently segments the dive + underwater dolphin kicks as
15 stroke cycles. After the fix, `ip_end` lands at the true breakout and the underwater kicks are
excluded — **without** touching the shared ridge the freestyle/backstroke segmenter counts cycles off,
and **without** regressing the 11/12 Mode-A sessions.

## Purpose
This is the reported segmentation bug. Its mechanism was pinned in 65-01: `_track_ridge`'s
`_RIDGE_LOW_BAND_BIAS = 0.5` tips a weak stroke fundamental down to the 0.25 Hz grid floor, so
`f_ref` (median of the ridge over the back 60% of the active run) reads ~0.33 Hz on butterfly whose
true rate is ~0.8–1.2 Hz. The `near`-frequency settle loop then finds "settled" from the very first
sample, and `ip_end` clamps to `b_end`. The coach sees a dive+kick block reported as cyclic stroking.

## Output
- `detect_swim_window` produces a correct `ip_end` on Mode-C sessions; Mode-A unchanged.
- `_cwt_ridge` / `_track_ridge` gain an optional `low_band_bias` argument **whose default reproduces
  today's behavior elementwise**, so `segment_cycles_wavelet` and every fixture score are untouched.
- `tools/underwater_probe.py` can dump the biased-vs-de-biased ridge for any session id.
</objective>
