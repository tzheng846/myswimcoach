<objective>
## Goal
Add cycle quality stats to `compute_session_metrics` and a `data_quality` object to the `/process` API response. Coach gets objective signal quality and segmentation confidence on every session without any extra effort.

## Purpose
All metrics downstream of segmentation are meaningless if segmentation produced bad cycles. This plan adds four key signals: (1) how many cycles were anomalously short ("outliers"), (2) how many were physically implausible, (3) what fraction of encoder samples had magnet dropout, and (4) a flag that kick metrics are unreliable at the default filter cutoff. These signals appear in the API response and are stored in `metrics_json` so the iOS report card can surface them.

## Output
- `metrics.py`: `session` dict gains 4 new keys: `total_cycles_raw`, `outlier_cycle_count`, `implausible_cycle_count`, `kick_metrics_reliable`
- `api.py`: response gains `data_quality` object; `data_quality` also stored in `metrics_json` in Supabase
</objective>

```python
# ── Magnet dropout fraction ───────────────────────────────────────────
_total_rows = 0
_dropout_rows = 0
try:
    _reader = _csv.DictReader(_io.StringIO(raw_bytes.decode("utf-8", errors="replace")))
    for _row in _reader:
        _total_rows += 1
        if _row.get("magnet_ok", "1") == "0":
            _dropout_rows += 1
except Exception:
    pass
magnet_dropout_pct = round(100.0 * _dropout_rows / _total_rows, 1) if _total_rows > 0 else 0.0
```
