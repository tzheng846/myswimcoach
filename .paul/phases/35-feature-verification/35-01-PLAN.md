<objective>
## Goal
Verify every web-facing feature Swimnetics claims to support actually works — marketing
site, public parent report pages, the authenticated coach portal, and the live
`/coach/chat` AI coaching loop — first against a local dev server (catch + fix code bugs
in one loop), then spot-checked against the deployed Vercel + Railway production. Produce
a single findings document classifying each surface **WORKING / BROKEN / DEFERRED**, and
fix any in-scope code bug found.

## Purpose
This is the "web" stage of the user's verification phase ("verify all features that are
supposed to work are in fact working"). Several web surfaces carry *deferred live
verification* in STATE — Phase 31/33 `/coach/chat` was never live-verified, and the
marketing/portal/report surfaces were last confirmed only in preview during their build
phases (23/24/29/30). This plan closes that gap before iOS (35-02) and the doc
reconciliation (35-03), which depend on what this turns up.

## Output
- `.paul/phases/35-feature-verification/35-01-WEB-FINDINGS.md` — per-surface WORKING/
  BROKEN/DEFERRED table with evidence (screenshots, console state, probe output).
- Code fixes in `web/**` for any in-scope bug found (each fix traced to a finding).
</objective>
